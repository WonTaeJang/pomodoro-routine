# 까미 돌봄 프로토타입

개발 서버의 `/pet`에서 체험합니다. 기존 타이머와 별도인 실험 페이지이며,
돌봄 기록은 이 브라우저의 localStorage에 저장합니다. 집중 보상과 서버 저장은 아직 연결하지 않았습니다.

## 동작

기획 결정은 [03-decisions.md](./03-decisions.md), 다음 작업은 [백로그](./backlog.md), 이미 구현한 돌봄 기능·수정은 [완료 목록](./backlog-completed.md)에서 관리합니다. 이 문서는 구현·재생성 방법을 설명합니다.

- 실제 Rive 파일에서 `Sleeping` → `Startled` → `Idle`과 돌봄 반응 `Happy`·`Snacking` 애니메이션을 재생합니다.
- 처음에는 앞발에 턱을 얹고 엎드려 잡니다. 호흡과 Z 표시가 반복되고, 수면 장면 시작 후 5초가 지나면 바로 대기 자세로 바뀝니다. 클릭·터치·Enter/Space로 깨우면 눈을 뜨고 머리 위 느낌표를 1초 표시한 뒤 대기로 전환합니다. 이때 호흡·Z 표시는 멈추고 추가 입력은 무시합니다. 몸을 일으키는 과정은 없습니다.
- 깨우기는 쓰담으로 세지 않습니다. 대기 상태부터 쓰다듬기를 받습니다. 다시 깨워보기는 누적 횟수를 유지하고 수면부터 다시 시작합니다.
- 강아지 또는 쓰다듬기 버튼 클릭, 터치, 누른 채 이동, 키보드 Enter/Space를 지원합니다.
- 쓰다듬기 반응은 2.8초 후 대기로 돌아갑니다.
- 깨어 있을 때 `간식 주기`를 누르면 황금빛 뼈 모양 비스킷을 받기(0.3초) → 씹기·양 끝부터 먹기·부스러기(0.9초) → 만족 표정·꼬리·하트(0.6초)를 재생합니다. 인정된 간식 한 번마다 친밀도 +3점, 일일 횟수·재고·집중/휴식 제한 없음. 간식 1.8초·쓰담 2.8초 반응 중에는 두 돌봄 버튼·강아지 직접 조작·다시 깨워보기를 비활성화합니다. 종료 후 다음 행동을 받으며 도중 입력은 예약하거나 적립하지 않습니다. 보상 지급·수량·제한은 I-033에서 나중에 추가합니다.
- 누적 쓰담 횟수는 새로고침·재방문에도 유지합니다. 화면에는 이름·상태·동작·누적 횟수만 남기고, 키보드 안내는 접근성 설명으로 제공합니다.
- 친밀도는 5단계(0·20·60·140·300점)이며 하루 첫 5번의 쓰담에 +2점씩 적립합니다. 한도 후에도 쓰담·기쁨 반응은 유지하고 미접속으로 감소하지 않습니다. 단계/진행 막대를 누르면 상세 점수·오늘 적립량을 펼칩니다. 단계 상승 때만 짧게 알리고, 단계별 모션은 I-031 후속입니다.
- 기기의 동작 줄이기 설정에서는 상태별 표정만 보여주고 움직임을 멈춥니다.
- 파일 로드 실패 시 다시 불러오기 버튼을 제공합니다.

- `src/features/pet/riveContract.test.ts`: 실제 RML 먹기 타임라인과 React 종료 시간의 일치 검증

- `scripts/generate-pet-rml.mjs`: 자체 제작 도트 그림과 타임라인을 재생성하는 스크립트
- Artboard: `Kkami`, State machine: `Pet`
- View model: `PetModel`, boolean properties: `isSleeping` (기본 true), `isStartled`·`isHappy`·`isSnacking` (기본 false), triggers: `sceneReady`·`snackAgain`

React의 `phase`와 타이머가 boolean을 갱신하면 Rive 상태 머신이 수면·놀람·대기·기쁨을 전환합니다. 자동 깨우기는 `PET_SLEEP_MS`(5초), 수동 깨우기 반응은 `PET_STARTLE_MS`(1000ms)로 관리합니다. `Startled`는 눈과 느낌표가 유지되는 정지 자세이며 React의 타이머가 대기로 전환합니다.

React는 ViewModel 구독을 준비한 뒤 재생합니다. Rive 초기 상태는 수면 그림을 유지하는 100ms 준비 상태를 거쳐 `Sleeping`에 들어가며 `sceneReady` 트리거를 보냅니다. 첫 프레임에서 구독 전에 신호가 사라지는 것을 피하고, 무료 플랜 시작 화면이 끝난 뒤 수면 장면부터 5초를 셉니다. 동작 줄이기에서도 시작 화면은 재생하고 `sceneReady` 이후에 자세를 정지합니다.
캐릭터는 4단위 격자의 사각형으로 제작했고 hold 키프레임을 사용합니다. 기존 모션은 12fps, `Snacking`은 20fps·36프레임(1.8초)입니다. 같은 먹기 타임라인을 쓰는 두 상태를 `snackAgain` 트리거로 교대로 진입해 먹기 진입 시 타임라인을 확실히 초기화합니다. 현재 React 입력 정책은 진행 중 재입력을 차단합니다(I-040). React의 `snackUntil`이 종료를 관리하고 모션 재생은 저장 횟수를 늘리지 않습니다.
Rive 내부 스크립트나 외부 캐릭터 에셋은 사용하지 않습니다.

## 돌봄 기록 저장

`kkamodoro-pet` 키에 `{ version: 3, state: { pet } }` 형식으로 저장합니다. `pet`은 `id`, `createdAt`, `totalPats`, `totalSnacks`, `lastPettedAt`, `updatedAt`, `affinity`를 포함합니다. 날짜는 밀리초 시각이며, 첫 쓰담 전 `lastPettedAt`은 null입니다. 최초 `/pet` 방문에서 기록을 만들고, 인정된 쓰담·간식마다 즉시 저장합니다. 간식은 마지막 쓰담 시각을 변경하지 않습니다.

`affinity`는 `points`와 `rewardedPats`(로컬 `YYYY-MM-DD`별 적립 쓰담 횟수, 최대 5)를 저장합니다. 적립 날짜를 유지하므로 자정 이후 늦은 재시도나 두 탭의 변경에도 같은 날짜의 한도를 넘지 않습니다. 단계는 점수에서 계산합니다. v3 점수는 날짜별 적립 쓰담 횟수 합계 × 2 + 누적 간식 횟수 × 3과 일치해야 유효합니다. 간식 횟수는 소비 재고가 아닌 지금까지 준 횟수입니다.

v1은 ID·누적 쓰담·시각을 유지하고 빈 친밀도(0점)로 읽습니다. 과거 날짜별 쓰담이 없어 소급 적립하지 않습니다. v2는 기존 친밀도·일일 적립 내역도 유지합니다. 두 버전 모두 간식 0회로 이전하며 첫 변경 저장 때 v3를 기록합니다. 새 버전을 읽을 수 없는 구버전 탭은 기존 버전 보호 규칙으로 쓰기를 멈춥니다.

수면·놀람·기쁨, 타이머와 포인터 상태는 저장하지 않습니다. 새로고침은 수면부터 시작하며 다시 깨워보기는 누적 기록을 지우지 않습니다. 설정의 "모든 데이터 지우기"는 2026-11-11에 없앴으므로(I-027), 지금은 화면에서 돌봄 기록을 지우는 방법이 없습니다 (`petStore.clear()`는 남겨 둠).

앱의 `useHydrateStores`에서 복원하고 `useTabSync`에서 다른 탭 변경을 반영합니다. 쓰기는 최신 기록을 다시 읽어 미저장 쓰담·간식을 합산합니다. Web Locks 지원 환경에서는 읽기·쓰기·삭제를 같은 잠금으로 직렬화합니다. 미지원 환경에서는 쓰기 직전 다시 읽지만 탭들이 정확히 동시에 쓰는 경우 합산을 보장하지 못합니다.

저장 오류는 메모리의 기록과 미저장 횟수를 유지하고 짧은 안내와 재시도만 표시합니다. 새로고침하면 미저장 기록은 사라질 수 있습니다. 손상된 값이나 더 높은 버전은 자동으로 덮어쓰지 않습니다. 마이그레이션은 `decodePet`에서 관리합니다. 미저장 돌봄은 날짜·행동 종류별 묶음으로 모아 저장된 원본에 다시 적용하며, 낙관적으로 표시한 친밀도를 다시 합산하지 않습니다.

미저장 횟수(`pendingPats`, `pendingSnacks`)와 재시도 대상(`retryOperation`: save/clear/null)을 별도로 관리합니다. 첫 읽기·저장 실패로 임시 ID가 생겼어도 복원 시 미저장 돌봄을 한 번 합산합니다. 반면 이미 확인한 ID가 다른 탭에서 삭제·교체되면 옛 미저장 돌봄을 버립니다. 단순 복원은 대기 중인 저장/삭제를 성공으로 처리하지 않습니다.

기록 ID 비교는 복원 때뿐 아니라 저장 잠금 안에서 최신 원본을 읽은 직후에도 수행합니다. 재시도는 초기화 전 대기 기록을 버리고, 새로 누른 행동은 그 한 건만 새 기록에 반영합니다. 그 저장도 실패하면 새 행동만 재시도에 남깁니다. 대기 기록 합산과 횟수 계산은 `pendingCare.ts`, 저장 성공·삭제·복원 시 대기 상태 해제는 `acceptSaved`로 통일합니다.

돌봄 반응은 중복 `reaction` 필드 없이 단계·종료 시각에서 파생합니다. 새 쓰담/간식 입력 전에 만료된 반응을 정리하므로 브라우저가 종료 콜백을 늦게 실행해도 이전 쓰담을 다시 예약하지 않습니다. 진행 중인 반응이 있으면 UI 비활성화와 별도로 reducer에서도 쓰담·간식을 거절합니다. 종료 경계부터 다음 행동을 인정합니다.

삭제 실패 후 재시도는 삭제를 수행합니다. 그 뒤 새 쓰담을 요청하면 기존 기록에 대한 새 저장 요청이 이전 실패한 삭제 요청을 대체하며, 이후 재시도가 갑자기 삭제를 수행하지 않습니다. 성공 시 재시도 대상을 해제합니다.

`PetRepository`는 저장 위치를 분리하는 경계입니다. 현재 구현은 게스트 로컬 저장뿐입니다. 로그인 기능을 추가할 때 계정용 서버 구현과 로그인 상태에 따른 선택, 게스트 기록 이전 정책을 별도로 연결합니다.

## Rive 에셋 다시 만들기

공식 Rive CLI 1.9.2로 제작·검증했습니다. CLI가 설치되어 있고 로그인되어 있어야
`.riv`를 내보낼 수 있습니다. `--publish=local`은 파일 내보내기이며 웹사이트를 공개하지 않습니다.

```sh
node scripts/generate-pet-rml.mjs
rive src/assets/kkami-pet --verify
rive inspect src/assets/kkami-pet --summary
rive src/assets/kkami-pet --publish=local --output-dir=../../../public/rive
```

원본 RML을 직접 수정하면 생성 스크립트 재실행 시 덮어써지므로, 반복적인 변경은
생성 스크립트에도 반영합니다. 스크립트의 `ID`는 RML의 고정 식별자 목록이며 숫자는 유지하고 이름으로 참조합니다. 구조만 리팩토링할 때는 생성 전후 RML의 바이트 동일성도 확인합니다. 무료 Rive Workspace에서 내보낸 현재 파일에는
Rive 시작 스플래시가 포함되어 있습니다.

`npm run dev`와 `npm run build`는 `scripts/copy-rive-runtime.mjs`로 설치된
`@rive-app/webgl2`와 같은 버전의 WASM을 `public/rive/rive.wasm`에 복사합니다.
이 생성 파일은 Git에서 제외하며, 브라우저는 외부 CDN 없이 로컬 파일을 사용합니다.
개발 서버가 이미 켜진 상태에서 처음 추가했다면 복사 스크립트를 한 번 실행합니다.

## 검증

Node.js 22.12 이상에서 `npm run test:run`, `npm run lint`, `npm run format:check`, `npm run build`를 실행합니다. 브라우저에서는 수면 → 수동 깨우기(느낌표 1초)/자동 깨우기(즉시) → 대기 → 클릭·드래그·Enter/Space → 기쁨 → 자동 대기 복귀, 깨우기 횟수 제외·재시작, 모바일 화면과 언어 전환을 확인합니다. 저장 검증에는 새로고침 후 누적 복원, 다시 깨워보기의 기록 유지, 두 탭 동기화, 저장 실패·손상·미래 버전 보호와 전체 초기화를 포함합니다.

새로고침 화면 (B-003, 2026-11-11 수정): 강아지가 준비될 때(`ready`)까지 불투명한 덮개가 방(창문, 화분, 말풍선)을 가립니다. 무료 플랜의 Rive 시작 화면은 덮개보다 위 레이어(`$dog-layer`)라 그대로 보이고, 파일을 다 받은 뒤에는 "불러오는 중…" 글을 지웁니다. 준비되면 덮개가 0.2초 동안 서서히 걷힙니다(움직임 줄이기면 바로). 시작 화면이 끝난 뒤 `sceneReady`까지 약 0.3초는 강아지만 먼저 보입니다. 불러오기 실패 안내와 "다시 불러오기"는 같은 덮개에 나옵니다.
