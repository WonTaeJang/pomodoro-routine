# 까미 돌봄 프로토타입

개발 서버의 `/pet`에서 체험합니다. 기존 타이머와 별도인 실험 페이지이며,
돌봄 기록은 이 브라우저의 localStorage에 저장하고, 로그인하면 계정과 맞춥니다([까미 기록 계정 저장](./03-decisions.md#pet-account-sync)). 집중 보상은 아직 연결하지 않았습니다.

## 동작

기획 결정은 [03-decisions.md](./03-decisions.md), 다음 작업은 [백로그](./backlog.md), 이미 구현한 돌봄 기능·수정은 [완료 목록](./backlog-completed.md)에서 관리합니다. 이 문서는 구현·재생성 방법을 설명합니다.

- 직접 만든 캔버스 재생기(`src/features/pet/pixel/`)로 `sleeping` → `startled` → `idle`과 돌봄 반응 `happy`·`snacking` 동작을 그립니다. 라이브러리·파일 내려받기 없이 첫 프레임부터 바로 보입니다.
- 처음에는 앞발에 턱을 얹고 엎드려 잡니다. 호흡과 Z 표시가 반복되고, 수면 장면 시작 후 5초가 지나면 바로 대기 자세로 바뀝니다. 클릭·터치·Enter/Space로 깨우면 눈을 뜨고 머리 위 느낌표를 1초 표시한 뒤 대기로 전환합니다. 이때 호흡·Z 표시는 멈추고 추가 입력은 무시합니다. 몸을 일으키는 과정은 없습니다.
- 다른 메뉴에 갔다가 돌아와도 새 방문으로 시작합니다(엎드려 자기·기록창 처음부터·까미 장면 처음부터). `cacheComponents`를 켜 둔 라우터가 떠난 페이지를 상태째 숨겨 두기 때문에, 주소가 `/pet`으로 돌아오면 `PetPlayground`가 방을 새로 그립니다.
- 깨우기는 쓰담으로 세지 않습니다. 대기 상태부터 쓰다듬기를 받습니다. 다시 잠든 모습은 페이지에 다시 들어오면 볼 수 있습니다(다시 깨워보기 버튼은 2026-11-15에 없앰).
- 강아지 또는 쓰다듬기 버튼 클릭, 터치, 누른 채 이동, 키보드 Enter/Space를 지원합니다.
- 쓰다듬기 반응은 2.8초 후 대기로 돌아갑니다.
- 깨어 있을 때 `간식 주기`를 누르면 황금빛 뼈 모양 비스킷을 받기(0.3초) → 씹기·양 끝부터 먹기·부스러기(0.9초) → 만족 표정·꼬리·하트(0.6초)를 재생합니다. 인정된 간식 한 번마다 친밀도 +3점. 간식은 하루(기기 로컬 날짜) 5번까지이고, 다 주면 간식 주기 버튼이 꺼진 버튼 색으로 바뀌며 누르면 주지 않고 기록창에 "오늘 간식 5번을 다 줬어요. 내일 또 줄게요!"가 남습니다. 개발 모드(`next dev`)에서는 테스트하기 쉽게 한도를 두지 않습니다(횟수는 그대로 셈). 재고·집중/휴식 제한은 없습니다. 간식 1.8초·쓰담 2.8초 반응 중에는 돌봄 버튼·강아지 직접 조작을 비활성화합니다. 종료 후 다음 행동을 받으며 도중 입력은 예약하거나 적립하지 않습니다. 보상 지급·수량·제한은 I-033에서 나중에 추가합니다.
- 누적 쓰담 횟수는 새로고침·재방문에도 유지합니다. 화면에는 이름·상태·동작·누적 횟수만 남기고, 키보드 안내는 접근성 설명으로 제공합니다.
- 화면은 휴대용 게임기 모양입니다. 본체(모드를 따르는 색) 위에 이름을 새기고, 검은 테두리 안의 액정 한 장에 헤더와 방을 넣습니다. 헤더는 벽보다 한 톤 진한 색이고 어두운 선 2px + 밝은 선 2px의 도트 턱으로 방과 나눕니다. 헤더 왼쪽은 상태 아이콘과 문구(편안해요 웃는 얼굴, 행복해요 하트, 자는 중 Zz, 깜짝! 느낌표, 맛있어요 뼈다귀, 산책 중 발바닥), 오른쪽은 레벨과 하트 5칸입니다. 액정 아래 둥근 버튼 3개(쓰다듬기 분홍·간식 노랑·산책 초록)는 누르면 눌려 들어가고, 못 누를 때는 눌린 채 회색으로 꺼집니다. 산책 중에는 같은 액정에서 화면만 바뀌고 버튼 자리에 돌아가기가 옵니다. 본체 아래에는 누적 쓰담만 둡니다. 넓은 화면에서는 본체 폭을 520px로 제한합니다.
- 친밀도는 5단계(0·20·60·140·300점)이며 하루 첫 5번의 쓰담에 +2점씩 적립합니다. 한도 후에도 쓰담·기쁨 반응은 유지하고 미접속으로 감소하지 않습니다. 하트는 지금 레벨에서 다음 레벨까지의 진행률만큼 반 칸(10%) 단위로 차고(`affinityHalves`), 실제 도달한 만큼만 채워 5칸이 모두 차는 순간이 곧 레벨업입니다. 최고 단계는 5칸을 모두 채우고 MAX를 붙입니다. 본체 아래 친밀도 카드는 처음부터 펼쳐져 있고, 카드 머리의 접기/펼치기나 헤더의 레벨·하트로 접고 폅니다(새로고침하면 다시 펼침). 단계가 오르면 헤더가 3.5초 동안 노란색으로 바뀌며 "Lv.N 달성! 하트 +1"을 보여주고 화면 낭독기에도 알립니다.
- 레벨 하트: Lv.2·3·4·5에 오를 때마다 하트를 하나씩, 모두 4개 받습니다(`levelHearts` = 레벨 − 1). 친밀도는 줄지 않으므로 따로 저장하지 않고 레벨에서 계산하며, 기능이 생기기 전에 오른 레벨의 하트도 바로 들어 있습니다. 아이템 상자 재료 탭의 7번째 칸(다른 아이템과 같은 색, 받기 전에는 실루엣·"아직 못 받음")에 개수가 보이고, 이번 방문 중 레벨이 오르면 아이템 버튼에 빨간 점이 붙습니다(상자를 열면 사라짐). 지금은 모으기만 합니다. 단계별 모션은 I-031 후속입니다.
- 기기의 동작 줄이기 설정에서는 상태별 표정만 보여주고 움직임을 멈춥니다.
- 파일 로드 실패 시 다시 불러오기 버튼을 제공합니다.

## 산책 (I-034)

- 산책 놀이 고르기(I-076): `산책하기`를 누르면 먼저 방 위에 놀이 목록(`WalkMenu`)이 뜹니다. 헤더는 "산책 놀이 고르기"와 놀이 수만큼의 점(`WalkMenuPick`), 버튼은 ◀ / ▶ / ✓ 시작 / ✕ 돌아가기(`WalkMenuPads`, 들어가면 초점 ✓, 닫으면 산책하기 버튼으로). 카드를 누르면 고르고, 고른 카드를 다시 누르면 시작합니다. 놀이 목록·해금 레벨·준비 여부와 카드 그림(42×26칸, 2px)은 `walkGames.ts`, 상태는 `useWalkMenu`(잠김·준비 중은 헤더 안내 2.5초, 고르는 동안에만). 목록은 방 레이어 중 맨 위(`$menu-layer`)라 까미·말풍선·상자를 덮고, 그동안 까미 누르기는 꺼집니다. 오늘 산책을 다 했으면 목록 없이 지금처럼 기록창에 한 줄. 지금 시작되는 놀이는 1번 산책뿐입니다.
- 산책(1번 놀이)을 시작하면 한 번 다녀옵니다. 방에서 돌아서 나간 뒤 첫 걸음부터 A → B 3초 걷기, B에서 1.5초 동안 멈춰 킁킁대고 줍기, B → C 2초 걷기, 1초 동안 바깥이 왼쪽으로 빠지며 방으로 돌아와 정면으로 섭니다(`walkTrip.ts`의 `TRIP`). 끝나면 자동으로 집 화면이 됩니다.
- 산책마다 아이템 하나를 줍습니다. 나뭇잎 25%, 나뭇가지 25%, 돌멩이 20%, 솔방울 12%, 꽃 12%, 공 6%(`items.ts`). 산책은 하루(기기 로컬 날짜) 5번까지이고, 다 하면 산책하기 버튼이 꺼진 버튼 색(눌린 모양은 아님)으로 바뀌고, 누르면 산책은 시작하지 않고 기록창에 "오늘 산책 5번을 다 했어요. 내일 또 가요!"가 남습니다(건너뛰기도 1번으로 셈). 개발 모드(`next dev`)에서는 테스트하기 쉽게 한도를 두지 않습니다(횟수는 그대로 셈). 줍는 순간 기록을 저장하고 액정 위에 "솔방울을 주웠어요!" 카드를 3초 띄웁니다.
- 산책 중 헤더 오른쪽은 산책 지도(집 ─ ✦ ─ 집)입니다. 발바닥 표시가 시간에 맞춰 움직이고, 주우면 ✦ 자리에 아이템 아이콘이 들어갑니다. 집에 오면 다시 레벨·하트로 돌아옵니다.
- 산책 중에도 버튼 4개는 그대로 두고, 쓰다듬기·간식·아이템은 눌린 채 꺼지며 산책하기 버튼이 "건너뛰기"(▸▸)로 바뀝니다. 초점은 건너뛰기에 남고, 집에 오면 다시 산책하기가 됩니다. 처음 하는 산책(저장된 산책 0번)은 건너뛰기도 꺼지고 버튼 아래에 "첫 산책은 끝까지 함께 걸어요"를 보여줍니다. 건너뛰면 B 전이면 그 자리에서 아이템을 정해 주고("산책을 건너뛰고 … 주워 왔어요"), B 뒤면 바로 집으로 옵니다. 줍기 카드는 집 화면에서도 남은 시간 동안 보입니다.
- 산책 장면은 집 장면과 같은 코드 묶음에 들어 있어 따로 받지 않습니다. 버튼을 누르면 바로 정면 자세에서 돌아서기 시작합니다(첫 걸음까지 약 0.7초).
- 캔버스를 쓸 수 없는 브라우저에서는 덮개에 "다시 시도"와 "집으로"를 보여줍니다. 집으로 가면 아이템 없이 돌아오고 산책 횟수도 늘지 않습니다.
- 시간은 장면의 첫 걸음(`WALK_STEP_MS`)부터 페이지가 직접 셉니다(`useWalkTrip`). 장면과 페이지 시계 모두 화면이 그려질 때만 흐르고, 프레임 사이가 길어도 100ms(`MAX_STEP_MS`)까지만 넘겨 함께 움직입니다. 탭이 숨으면 둘 다 멈춥니다. 동작 줄이기에서는 장면이 첫 걸음 자세에서 멈추고 지도·카드·자동 복귀만 진행합니다.
- 산책하기 옆 "아이템" 버튼이 아이템 상자를 엽니다. 산책 아이템 6칸과 레벨 하트 1칸에 아이콘·이름·개수를 보여주고 못 찾은 아이템은 실루엣과 "???"로 둡니다. 새로 주운 아이템이 있으면 버튼에 빨간 점이 뜨고, 상자를 열면 사라집니다.
- 수면·놀람·쓰담·간식 반응 중에는 산책 버튼을 비활성화하고 reducer에서도 진입을 거절합니다. 산책 중에는 집의 돌봄 조작을 숨기고 늦게 도착한 돌봄·초기화 입력도 무시합니다. 복귀하면 다시 잠들지 않고 대기하며 산책 버튼으로 키보드 초점을 돌려줍니다. 집 까미 재생기는 유지하되 산책 동안 멈춥니다.
- 산책 장면은 진입할 때 새로 만들고, 첫 프레임을 그릴 때까지 집 방 위에 보이지 않게 겹쳐 두며 그동안 집 방이 그대로 보입니다(2026-11-21, 산책 시작 때 베이지 덮개가 깜빡이던 문제). 첫 프레임이 그려지면 한 프레임에 바뀝니다. 걸음마다의 산책은 집에 돌아온 시각(`homeAt`)으로 구분합니다. 덮개는 그리기에 실패했을 때만 보입니다.
- 새로고침·페이지 이탈은 산책을 끝냅니다. B에서 이미 주운 아이템은 저장돼 있습니다.
- 아이템을 문 모습, 조합식·가구, 집 배치(I-035)는 후속 범위입니다.

## 기록창

- 본체 아래에 이번 방문 동안 한 일을 최신순으로 보여줍니다(`usePetLog`, 메모리에만 최대 30줄, 새로고침하면 비움). 기본 5줄, 맨 아래 "더 보기 (N)"으로 전체를 펼칩니다. 카드 머리의 접기/펼치기로 기록창 전체를 접습니다(친밀도 카드와 같은 `PetPanel`). 맨 위 새 줄은 잠깐 강조합니다.
- 넓은 화면(1024px 이상)에서는 기록창이 본체 오른쪽 칸(240~320px)에 붙고, 본체는 화면 가운데에 그대로 있습니다. 양쪽 칸 너비를 같게 두어 중앙을 맞추며, 칸이 좁으면 본체가 먼저 줄어듭니다(1024px에서 448px). 그보다 좁으면 지금처럼 본체 아래에 옵니다.
- 남기는 일: 까미를 만나러 왔어요(페이지 진입), 까미가 일어났어요, 쓰다듬었어요(+점수·누적 N번), 간식을 줬어요(+3), 산책을 나갔어요, … 주웠어요, 집에 돌아왔어요, 산책을 건너뛰고 … 주워 왔어요, Lv.N 달성! 하트를 받았어요, … 만들었어요, 창문을 …로 바꿨어요, 오늘 산책 5번을 다 했어요. 무시된 입력과 상자 열기 같은 조작은 남기지 않습니다.
- 쓰담·간식은 저장된 기록이 늘어날 때 남깁니다. 시각은 시:분입니다. 화면 낭독기는 새 줄을 읽지 않고, 줍기 카드와 헤더 상태가 알립니다.

`components/PetWalk.tsx`는 산책 화면·재시도·집으로 UI를(재생은 `useWalkSprite`), `components/PetTrip.tsx`는 산책 지도와 줍기 카드를 담당합니다. 산책 장면은 `sprites/walkScene.ts`(680×320단위)이고, 층(layer) 다섯 개가 나란히 각자의 동작을 이어 재생합니다: 까미(정면·돌아서기 → 걸어 나가기 → 줍기 → 돌아오기 → 도착), 바깥, 길, 나무, 구름. 시간대는 페이지가 기기 시계(`useTimeOfDay`, 집 창밖과 같은 경계)로 넘기면 하늘(새벽 띠·떠오르는 해, 노을·지는 해, 밤하늘·초승달·별)을 바꾸고, 땅에는 같은 색의 반투명 그늘, 나무는 그 그늘을 미리 섞은 색으로 바꿉니다. 밤에는 구름을 숨깁니다(I-054).

산책 까미는 집 까미와 같은 방식으로 직접 그립니다. `sprites/walkSprite.ts`가 도트 데이터와 자세 계산을, `sprites/walkScene.ts`가 장면과 동작을 만듭니다. 한 칸은 4단위로 집과 같은 격자이고, 색은 집 팔레트(먹색·털색·밝은 털·크림·목줄·태그)만 씁니다. 머리는 집의 대기 머리를 그대로 가져와 눈과 주둥이만 걷는 방향으로 두 칸 옮긴 3/4 모습이고, 먼 귀는 머리 뒤로 접습니다. 같은 색은 줄 단위로 묶어 사각형 수를 줄이고, 먹색 실루엣을 아래에 깝니다.

산책 화면은 집 방과 같은 틀(여백·둥근 모서리·높이)을 쓰고, 덮개(안내·다시 시도)는 그리기에 실패했을 때만 씁니다. 방의 창문·화분·러그는 `PetRoomArt`로 집과 함께 쓰고, 레이어 순서는 `_room-layers.scss`로 맞춥니다. 장면은 680×320단위이고 캔버스를 CSS에서 집 강아지와 같은 배율(휴대폰 1배, sm 이상 1.2배)로 고정합니다. 휴대폰 방 높이(316px)보다 커서 바깥 풍경이 방을 빈틈없이 덮습니다. 발바닥 높이도 집과 맞추고, 머리를 가운데 두어 몸통이 뒤로 이어지게 합니다.

진입하면 방 안 러그 위에서 집의 대기 자세와 칸 단위로 같은 정면 까미가 같은 자리에 0.5초 서 있다가, 돌아서는 프레임 2장을 거쳐 걷기 시작합니다. 이때까지 캔버스는 비어 있어 페이지가 그린 방이 그대로 보입니다. 첫 걸음과 함께 바깥 풍경(`Outdoors` 노드)이 오른쪽에서 프레임마다 68단위(17칸)씩 밀려 들어와 0.8초 만에 방을 덮고, 길·나무·구름도 이때부터 움직입니다. 첫 프레임을 그리면 덮개를 걷고, 첫 걸음에서 페이지에 알립니다. 동작 줄이기에서는 시작 장면을 재생한 뒤 첫 걸음 자세(방 안)에서 멈춥니다. 돌아가기는 지금처럼 바로 집으로 바뀌며 집에서는 정면 대기 자세로 이어집니다.

걷기는 12fps·12프레임(1초 한 걸음)이고, 프레임마다 손으로 그린 다리 자세를 바꿔 끼웁니다. 늘리거나 소수점 단위로 옮기지 않습니다. 디딘 발은 프레임마다 정확히 한 칸 뒤로 가고 길도 같은 속도(초당 48단위)로 흘러 미끄러지지 않습니다. 앞다리와 반대쪽 뒷다리가 함께 움직이며 언제나 두 발 이상 땅을 딛고, 든 발은 최대 두 칸 올라가며 발끝을 한 칸 뒤로 접습니다. 다리가 몸 밑을 지날 때 몸과 머리가 한 칸 오르고, 꼬리는 세 프레임마다 좌우로 흔들립니다. 가까운 귀는 머리와 별도 노드로 두어 몸이 오를 때 한 칸 늦게 내려가 있고 내려올 때 한 칸 늦게 올라가 출렁입니다. 귀 뿌리 한 줄은 머리에 남겨 두어 귀가 내려가도 위쪽에 빈 틈이 생기지 않습니다. 배경은 길 12fps, 나무 6fps, 구름 2fps로 각 단계마다 정확히 한 칸씩 움직여 번지지 않습니다.

`walkSprite.test.ts`는 발과 길의 이동량, 지지 발 수, 대각선 다리 짝, 귀 출렁임 박자, 정면 자세와 집 대기 까미의 칸 단위 일치, 팔레트·4단위 격자, 동작 길이·시작 순서·풍경 속도·시간대를 검증합니다.

## 방 꾸미기 (I-035)

- 자리 4곳(벽·바닥·창문·화분·카펫, 꾸미기 순서)에 기본 모양 1개와 만들 수 있는 모양 3개씩. 벽과 바닥은 한 세트(나무 오두막·파스텔 꽃무늬·줄무늬 클래식), 카펫은 따로(꼬임 러그·분홍 물결 러그·술 달린 푸른 러그)라 섞어 쓸 수 있습니다. 레시피는 `furniture.ts`의 `FURNITURE`이고 모두 재료 3개(한 종류 2개 + 다른 종류 1개), 12개 조합은 서로 다릅니다.
- 아이템 상자의 꾸미기 탭(2026-11-21에 "만들기"에서 이름을 바꿈): 위의 자리 탭(벽·바닥·창문·화분·카펫·옷, 글자 대신 도트 아이콘이고 화면 낭독기에는 이름)으로 고른 자리의 것만, 그림·이름·재료(남은 수/필요 수)·버튼(만들기 / 재료 부족). 만든 것은 재료를 감추고 이름과 "적용" 버튼만 보이며, 누르면 상자는 열린 채로 그 자리에 바로 놓이고, 꾸미기 모드에서 놓은 것처럼 까미가 기뻐하고 기록창에 남습니다(여러 개를 이어서 적용할 수 있음). 지금 놓여 있는 것은 버튼 대신 포인트 색 테두리 카드와 "✓ 적용 중" 알약(`CheckIcon`, `data-applied`). 목록 맨 앞에는 처음부터 있는 것(기본 모양, 옷 자리는 갈색 모자도)이 "기본 제공" 표시와 "적용" 버튼으로 나옵니다. 만들면 재료가 빠지고 가구는 없어지지 않습니다. 아래 "방 꾸미기"(갈색 모자가 있어 늘 켜짐)로 꾸미기 모드에 들어갑니다. 재료 탭(2026-11-21에 "아이템"에서 이름을 바꿈)의 수량은 남은 수이고, 한 번이라도 찾은 아이템은 0개여도 이름이 보입니다.
- VIP 세트(I-071): 아이돌 무대 세트와 응원 피켓 말풍선은 `vip` 조각이라 만들 수 없고, VIP 계정의 꾸미기 탭에 금빛 "VIP" 표시와 "적용"으로, 세트 탭에 VIP 표시와 4/4로 나옵니다. `usePetVip`이 로그인·VIP 확인으로 VIP인지(모르면 null)를 알려 주고, VIP가 아니면 방·말풍선·꾸미기 모드·상자에서 빼고(`shownPlaced`), 놓여 있던 것은 한 번에 기본 모양으로 저장합니다(`useVipRoomCleanup`, `recordPlaceAll`에 null).
- 눈송이 상자(I-074): `useDailyBoxes`가 11~2월(기기 날짜)에 오늘 아직 안 받았으면 상자를 놓음. VIP 상자와 함께면 `PetPlayground`가 방 바닥에 겹쳐 쌓고(`pileBox`, 3개까지) 맨 위부터 차례로 엶(`boxes.step` "1/2"). 팝업은 `DailyBoxDialog`를 함께 쓰고(`PetSnowBox`·`PetGiftBox`), 첫 눈송이 상자는 크리스마스 꾸미기 6가지 안내. 받기는 `recordSnow`(돌봄 기록 `snow`, `receiveSnow`). 눈송이를 받은 뒤(`hasSnow`) 아이템 상자에 눈송이 칸·크리스마스 꾸미기(`recipesFor`)·세트(`setsFor`)가 보이고 시즌 테두리(`data-season`, 모서리 눈송이 `SeasonMark`). 크리스마스트리는 화분보다 커서 작은 그림은 긴 쪽에 맞춤(`LookPicture`의 `fit`).
- VIP 선물 상자(I-070): `useDailyBoxes`가 VIP이고 오늘(기기 날짜) 아직 안 받았으면 방 바닥 왼쪽에 상자(`BoxIcon`)를 놓고 헤더에 "VIP 선물 상자가 왔어요!"(레벨업 → 에디션 → 산책·꾸미기 다음). 누르면 `PetGiftBox` 팝업: 상자가 흔들리다 열리고(CSS만, 움직임 줄이기면 바로 열림) 재료 6칸 +1, 첫 상자(`gifts === 0`)에만 VIP 세트 안내와 "세트 보러 가기". 받기는 `recordGift`(돌봄 기록 `gift`, `receiveGift`), 기록창 한 줄, 까미 반응. 아이템 상자 "얻는 방법"에 VIP만 선물 상자 줄.
- 아이템 상자의 세트 탭(I-069): `SETS`의 세트마다 카드 하나(이름 · 만든 수 · 조각 그림 넷, 안 만든 조각은 흐리게 "?"). 넷을 다 만들면 "적용"으로 바뀐 자리만 `recordPlaceAll`로 한 번에 저장하고(화면 갱신·저장 각 한 번), 기록창에 세트 한 줄, 까미 반응은 한 번이며, 상자가 닫혀 바뀐 방이 바로 보입니다(꾸미기 탭의 낱개 "적용"은 상자를 열어 둔 채). 다 놓여 있으면 꾸미기 카드처럼 "✓ 적용 중", 하나라도 없으면 버튼이 없습니다. 버튼 왼쪽에는 세트마다 한 줄 소개(`items.sets.<id>.intro`)가 늘 보입니다. 옷·말풍선은 그대로입니다.
- 꾸미기 모드: 헤더가 "꾸미는 중"과 자리 이름·점(고를 수 있는 개수)으로 바뀌고, 버튼 4개가 ◀ 이전 / ▶ 다음 / ✓ 고르기·놓기 / ✕ 끝내기·뒤로가 됩니다. 먼저 자리를 고르고(방의 창문·화분·카펫, 그 밖의 벽·바닥을 직접 눌러도 됨) 다음 모양을 넘기면 방에 바로 미리 보입니다. 만든 모양만 넘겨 보며, 고른 자리는 점선 테두리가 깜빡이고(동작 줄이기면 멈춤, 벽·바닥은 방 안쪽 둘레) 이름표가 붙습니다. 놓으면 자리 고르기로 돌아가 다른 자리를 이어서 꾸밀 수 있고(끝내기는 자리 고르기에서 ✕), 까미가 깨어 있으면 기뻐하며 꾸민 뒤 말풍선(예: "방이 예뻐졌어!"), 기록창에 "창문을 꽃 장식 창으로 바꿨어요"가 남습니다(쓰담 횟수·친밀도에는 들어가지 않음). 들어갈 때 초점은 ✓, 끝나면 아이템 버튼으로 돌아갑니다. 꾸미는 동안 까미 직접 조작은 막고, 꺼진 까미 영역은 눌림을 통과시켜 아래 카펫을 고를 수 있습니다.
- 창문·화분은 `roomArt.ts`의 도트 그림이고 집 까미와 같은 칸 크기(`--room-cell`: 4.8px, 좁은 화면 4px)로 그립니다. 창은 창밖을 먼저 그리고 창틀을 덮어, 기기 시계에 따라 새벽(5–7시)·낮(7–17시)·해질녘(17–19시)·밤(19–5시) 하늘이 모든 창에 들어갑니다(`useTimeOfDay`, 경계에서 바로 바뀜, 탭이 다시 보일 때도 확인). 서버 렌더링은 낮으로 그리고 브라우저에서 맞춥니다. 개발 중에는 `/pet?time=dusk`처럼 시간대를 미리 볼 수 있습니다. 방 전체 밝기는 바꾸지 않으며, 산책 출발 장면도 같은 방 그림이라 놓은 가구가 그대로 보입니다. 산책 바깥 하늘의 시간대는 I-054.
- 벽·바닥과 카펫도 같은 칸 크기의 도트 그림입니다. 벽·바닥은 방 크기에 맞춰 반복 무늬(`ROOMS`의 `tile`)를 CSS 배경으로 깔고, 벽 아래 띠(판벽·걸레받이)와 바닥 첫 줄(`edge`)을 바닥선에 맞춰 덧댑니다. 카펫은 `rugArt`로 바닥에서 45×12칸 안팎, 상자·기록창에는 작게 그립니다. 기본 벽·바닥과 기본 러그는 지금처럼 방 CSS가 그립니다. 집 까미 장면의 발밑 밝은 띠는 카펫과 겹치지 않게 뺐습니다(I-056).

## 게임기 에디션 (궁전 I-067, VIP I-071, 크리스마스 I-075)

- 궁전 세트 넷(궁전 방·금테 아치 창·금빛 장미 화분·페르시안 러그)을 모두 놓으면 본체에 `data-edition="palace"`가 붙어 버건디 본체 · 금테 · 금 이름 · 금 테두리 버튼(`::after`로 겹침, 눌림 그림자와 따로) · 크림빛 헤더로 바뀌고, 도트 왕관(`EditionMark`)이 본체 윗변에 걸쳐 앉습니다. 색은 `_device.scss`의 `$palace-*`이고 모드와 관계없습니다. 왕관 자리만큼 본체 위 여백이 늘어납니다.
- 바뀔 때는 배경·테두리·그림자가 0.6초 동안 서서히, 왕관은 위에서 살짝 내려앉으며 나타납니다(동작 줄이기면 바로). 하나라도 바꾸면 원래 본체로 돌아갑니다.
- `useDeviceEdition`이 저장소 변화를 보고, 같은 까미에서 넷이 막 갖춰졌을 때만 3.5초 동안 헤더를 금빛 "궁전 에디션이 됐어요!"(VIP 에디션은 "VIP 에디션이 됐어요!")로 바꾸고 기록창에 한 줄 남깁니다. 페이지를 열 때 이미 궁전이면 안내하지 않습니다. 헤더 우선순위는 레벨업 → 에디션 → 산책·꾸미기 → 자세입니다.
- VIP 에디션: 아이돌 무대 세트 넷을 모두 놓으면 `data-edition="stage"`로 연보라 본체 · 핫핑크 테두리 · 흰 이름에 핑크 외곽 · 연분홍 헤더 · 핫핑크 테두리 버튼, 본체 윗변에 큰 핑크 리본(`EditionMark`)이 앉습니다. 색은 `_device.scss`의 `$stage-*`. 두 에디션 모두 같은 `edition` 믹스인으로 그리고, 어떤 에디션인지는 세트의 `edition` 표시로 정합니다(`editionOf`). VIP가 아니면 세트를 빼고 보므로 VIP 에디션도 없습니다.
- 크리스마스 에디션: 크리스마스 세트 넷을 모두 놓으면 `data-edition="christmas"`로 빨간 본체 · 금테 · 흰 이름 · 크림빛 헤더(`$xmas-*`). 장식은 가운데 하나가 아니라(`EditionDecor`) `DeviceSleigh`가 본체에 붙이는 그림들(`SleighArt`, 3px 칸): 위 왼쪽 선물 짐(`cargo`), 오른쪽 루돌프(`deer`)와 고삐, 아래 금빛 썰매 날(기둥 셋)과 앞머리(`curl`). 썰매 날만큼 본체 아래 여백이 늘어납니다. 루돌프 코는 `PixelIcon`의 `cellClass`로 그 색 칸에만 깜빡임(`.nose`)을 줍니다.
- 크리스마스 방 움직임: `PetRoomArt`가 크리스마스 에디션이고 꾸미는 중이 아닐 때 `ChristmasSky`(눈송이 11개, 날아가는 썰매 행렬 `SleighArt part="team"`, 2px 칸)와 창문 위 `WindowLights`(전구 칸 `XMAS_LIGHT_CELLS`에 어두운 칸을 번갈아 덮음)를 그립니다. 모두 CSS 애니메이션이고, 썰매는 60초 주기 중 앞의 12%(7초쯤)만 지나가며 처음은 4초 뒤입니다. 까미 캔버스와 말풍선보다 아래 겹이라 그 뒤로 지나갑니다. 움직임 줄이기면 숨김(전구는 켜진 그림 그대로).
- 색만 바뀌는 본체: 숲속 오두막·파스텔 꽃·줄무늬 클래식 세트(`tint`)는 넷을 모두 놓으면 본체에 `data-tint`가 붙어 `--shell`만 원목 브라운·벚꽃 분홍·블루그레이로 바뀝니다(`$tint-shells`). 그림자·밝은 선·이름 톤은 `.device`가 본체 색에서 만들고, 본체 위 글자색(`--color-text`)은 모드와 관계없이 `$tint-ink`. 안내·기록·장식은 없습니다(`tintOf`, `useDeviceEdition`의 `tint`).

## 까미 옷 (I-061)

- 꾸미기 자리 "옷"(꾸미기 순서의 마지막). 기본은 목줄과 이름표("기본 목줄"), 갈색 모자는 처음부터 고를 수 있고, 파란 깅엄 스카프(하트 1 + 꽃 2)·크림 스카프(하트 1 + 나뭇잎 2)·하늘색 체크 셔츠(하트 1 + 돌멩이 2)·넥카라(하트 1 + 공 2)는 만들어서 고릅니다. 한 번에 하나만 입습니다. 만들기 탭의 옷(셔츠 아이콘) 탭에 4개가 있고, 하트가 모자라면 재료 부족입니다. "방 꾸미기"는 모자가 있어 늘 켜져 있습니다.
- 집 까미 장면(`sprites/homeScene.ts`)에 옷마다 서 있는 자세·누운 자세 노드를 그리고(`sprites/outfitCells.ts`), 페이지는 놓은 옷(꾸미는 중이면 미리 보는 옷)의 두 노드만 보이게 합니다. 모자는 머리 노드에, 나머지는 몸 위·머리 아래에 있어 자세·움직임을 그대로 따라갑니다. 상자·기록창의 옷 그림은 같은 데이터에서 서 있는 옷만 떼어 그립니다. 꾸미기 모드에서 까미를 누르면 옷 자리로 갑니다. 산책 까미는 아직 옷을 입지 않습니다.

## 까미 말풍선 (I-058)

- 문장은 문구 사전의 `pet.speech`에 상황별·친밀도 레벨(lv1~5)별로 있습니다. Lv.1은 "멍?", "킁킁…" 같은 강아지 소리만, Lv.2는 소리에 단어가 섞이고, Lv.3부터 짧은 문장, Lv.4부터 시간대(새벽·낮·해질녘·밤, 창밖과 같은 기준) 이야기, Lv.5는 다정한 말까지 합니다. Lv.1~3의 밤 대기에는 "하암…" 같은 졸린 소리가 섞입니다.
- 상황은 우선순위대로 하나: 잠(모든 레벨 "쿨쿨…") → 레벨업 순간(그 레벨의 첫 말, 헤더의 "Lv.N 달성!" 동안) → 깨어남(놀람 1초와 깬 뒤 4초) → 간식 → 꾸민 뒤 → 쓰다듬기 → 산책에서 돌아온 뒤 8초 → 대기.
- 상황이 바뀔 때마다 하나를 고르고, 대기 문장은 1분마다 바뀝니다. 같은 상황의 바로 전 문장은 다시 고르지 않고, 20% 확률로 아래 레벨 문장이 섞입니다(단짝도 가끔 "멍!"). 고르기는 브라우저에서 화면을 그린 뒤 하므로 서버 렌더링과 어긋나지 않습니다. 깨어난 시각·돌아온 시각은 돌봄 상태(`awakeAt`·`homeAt`)에 남겨, 상황이 바뀌는 사이에 다른 문장이 끼지 않습니다.
- 말풍선은 글만(아이콘 없음), 까미가 움직여도 겹치지 않게 머리 위로 약 30px 띄웁니다(`$bubble-top`). 꼬리는 오른쪽 변이 세로로 떨어지는 직각삼각형(`BubbleTail`, 16×14)이고 끝이 머리 가운데를 가리킵니다.
- 휴식·집중 같은 타이머 상황 문장은 I-033과 함께 나중에.

## 까미 그리기 (2026-11-20, I-068)

까미와 산책 장면은 `src/features/pet/pixel/`의 작은 재생기로 캔버스에 그립니다. 예전에는 Rive 파일로 재생했지만, 그림을 스크립트로 만들고 한 장씩 넘기는 움직임만 써서 직접 그리도록 바꿨습니다.

- **장면(`scene.ts`)**: 사각형(`rect`)과 노드(`node`, 위치·배율·보이기를 함께 바꾸는 묶음)의 나무. 좌표는 장면 단위이고 도트 한 칸은 4단위(`CELL`)입니다. 자식은 뒤에서 앞 순서로 그립니다. 움직이는 노드만 `id`를 가집니다.
- **동작(`timeline.ts`)**: 노드별 `[프레임, 값]` 키(`keys`). 기본은 다음 키까지 값을 유지하고, 풍경처럼 미끄러지는 것만 직선(`linear`)이되 프레임 단위로 끊어 셉니다. 동작(`clip`)은 fps·길이·반복 여부를 가지며, 반복하지 않으면 마지막 프레임에 멈춥니다. 이어 붙인 동작(`applySequence`)에서는 앞 동작이 정한 값이 다음 동작이 바꿀 때까지 남습니다.
- **상태 머신(`machine.ts`)**: 상태마다 동작 하나. 입력 값, 한 번 보내는 신호, 동작 끝남으로 넘어가며, 앞 상태가 남긴 값은 이어집니다. 화면 없이 계산만 하는 순수 함수라 테스트로 확인합니다.
- **그리기(`render.ts`)**: 노드마다 위치·배율을 쌓아 사각형을 칠합니다. 모서리를 기기 픽셀에 맞춰 반올림해 1.2배처럼 정수가 아닌 배율에서도 칸 사이에 틈이나 번짐이 없습니다. `rasterize`는 같은 장면을 칸 단위 색으로 돌려줘 테스트에 씁니다.
- **재생(`usePixelCanvas.ts`)**: 캔버스를 CSS 크기 × 기기 픽셀 배율로 잡고(확대·축소도 따라감) 화면 갱신마다 시간을 넘기되, 그림이 실제로 바뀌는 프레임에서만 다시 칠합니다(대기 중인 까미는 3초에 5번 안팎). 탭이 숨으면 멈추고 돌아와도 건너뛰지 않습니다.

옮길 때 예전 Rive 장면과 비교했습니다: 집 까미의 모든 동작·모든 프레임·모든 옷, 산책의 네 시간대를 1/24초마다 칸 단위로 같고, 실제 화면도 휴대폰 배율에서 픽셀 단위로 같습니다(1.2배에서는 Rive가 칸 가장자리를 흐리게 칠하던 1px만 다름).

## 돌봄 기록 저장

`kkamodoro-pet` 키에 `{ version: 6, state: { pet } }` 형식으로 저장합니다. `pet`은 `id`, `createdAt`, `totalPats`, `totalSnacks`, `lastPettedAt`, `updatedAt`, `affinity`, `walks`, `items`, `itemsSeen`, `spent`, `furniture`, `placed`, `walkDay`, `walksOnDay`를 포함합니다. 날짜는 밀리초 시각이며, 첫 쓰담 전 `lastPettedAt`은 null입니다. 최초 `/pet` 방문에서 기록을 만들고, 인정된 쓰담·간식마다 즉시 저장합니다. 간식은 마지막 쓰담 시각을 변경하지 않습니다.

`affinity`는 `points`와 `rewardedPats`(로컬 `YYYY-MM-DD`별 적립 쓰담 횟수, 최대 5)를 저장합니다. 적립 날짜를 유지하므로 자정 이후 늦은 재시도나 두 탭의 변경에도 같은 날짜의 한도를 넘지 않습니다. 단계는 점수에서 계산합니다. v3 점수는 날짜별 적립 쓰담 횟수 합계 × 2 + 누적 간식 횟수 × 3과 일치해야 유효합니다. 간식 횟수는 소비 재고가 아닌 지금까지 준 횟수입니다.

v1은 ID·누적 쓰담·시각을 유지하고 빈 친밀도(0점)로 읽습니다. 과거 날짜별 쓰담이 없어 소급 적립하지 않습니다. v2는 기존 친밀도·일일 적립 내역도 유지합니다. 두 버전 모두 간식 0회로 이전합니다. v3까지는 산책 0번·빈 상자로 읽고, 첫 변경 저장 때 v4를 기록합니다. v4는 산책마다 아이템 하나라서 `items` 합계가 `walks`와 같아야 하고, `itemsSeen`(상자를 마지막으로 열었을 때 찾은 수)은 그보다 클 수 없습니다. 산책·확인 표시도 쓰담·간식과 같은 대기 기록으로 저장해 재시도해도 두 번 들어가지 않습니다. v4까지는 가구 없이(`spent`·`furniture`·`placed` 비움) 읽습니다. v5의 `items`는 지금까지 찾은 수 그대로이고 만들기에 쓴 수는 `spent`에 따로 쌓아(아이템마다 찾은 수 이하) 산책 횟수 검사를 유지합니다. `furniture`는 만든 가구(중복 없음), `placed`는 자리별로 놓은 가구(만든 것이고 자리가 맞아야 함, 없으면 기본 모양)입니다. 만들기·놓기도 대기 기록으로 저장하며, 같은 가구 만들기는 한 번만, 같은 자리 놓기는 마지막 선택만 남깁니다. v5까지는 오늘 산책 0번(`walkDay` null)으로 읽습니다. v6의 `walkDay`·`walksOnDay`는 마지막으로 산책한 로컬 날짜와 그날 횟수(전체 산책 수 이하)로, 더 늦은 날이면 다시 세고 늦게 저장된 지난날 산책은 그날 횟수를 바꾸지 않습니다. v7은 v6와 모양이 같고 벽·바닥·카펫 가구와 자리(`room`·`rug`)가 더해져, 이를 모르는 구버전이 기록을 덮어쓰지 않게 버전만 올렸습니다. v8도 모양은 같고 까미 옷 자리(`outfit`)와 옷 가구가 더해집니다. v9는 `snackDay`·`snacksOnDay`(마지막으로 간식을 준 로컬 날짜와 그날 횟수, 전체 간식 수 이하)를 더하고, v8까지는 오늘 간식 0번으로 읽습니다. 옷에 쓴 하트는 따로 저장하지 않고 만든 옷에서 세며, 받은 하트(레벨 − 1)를 넘을 수 없습니다. 갈색 모자는 만들지 않아도 놓을 수 있고 `furniture`에는 들어가지 않습니다. 새 버전을 읽을 수 없는 구버전 탭은 기존 버전 보호 규칙으로 쓰기를 멈춥니다.

수면·놀람·기쁨, 타이머와 포인터 상태는 저장하지 않습니다. 새로고침은 수면부터 시작하며 누적 기록은 그대로입니다. 설정의 "모든 데이터 지우기"는 2026-11-11에 없앴으므로(I-027), 지금은 화면에서 돌봄 기록을 지우는 방법이 없습니다 (`petStore.clear()`는 남겨 둠).

앱의 `useHydrateStores`에서 복원하고 `useTabSync`에서 다른 탭 변경을 반영합니다. 쓰기는 최신 기록을 다시 읽어 미저장 쓰담·간식을 합산합니다. Web Locks 지원 환경에서는 읽기·쓰기·삭제를 같은 잠금으로 직렬화합니다. 미지원 환경에서는 쓰기 직전 다시 읽지만 탭들이 정확히 동시에 쓰는 경우 합산을 보장하지 못합니다.

저장 오류는 메모리의 기록과 미저장 횟수를 유지하고 짧은 안내와 재시도만 표시합니다. 새로고침하면 미저장 기록은 사라질 수 있습니다. 손상된 값이나 더 높은 버전은 자동으로 덮어쓰지 않습니다. 마이그레이션은 `decodePet`에서 관리합니다. 미저장 돌봄은 날짜·행동 종류별 묶음으로 모아 저장된 원본에 다시 적용하며, 낙관적으로 표시한 친밀도를 다시 합산하지 않습니다.

미저장 횟수(`pendingPats`, `pendingSnacks`)와 재시도 대상(`retryOperation`: save/clear/null)을 별도로 관리합니다. 첫 읽기·저장 실패로 임시 ID가 생겼어도 복원 시 미저장 돌봄을 한 번 합산합니다. 반면 이미 확인한 ID가 다른 탭에서 삭제·교체되면 옛 미저장 돌봄을 버립니다. 단순 복원은 대기 중인 저장/삭제를 성공으로 처리하지 않습니다.

기록 ID 비교는 복원 때뿐 아니라 저장 잠금 안에서 최신 원본을 읽은 직후에도 수행합니다. 재시도는 초기화 전 대기 기록을 버리고, 새로 누른 행동은 그 한 건만 새 기록에 반영합니다. 그 저장도 실패하면 새 행동만 재시도에 남깁니다. 대기 기록 합산과 횟수 계산은 `pendingCare.ts`, 저장 성공·삭제·복원 시 대기 상태 해제는 `acceptSaved`로 통일합니다.

돌봄 반응은 중복 `reaction` 필드 없이 단계·종료 시각에서 파생합니다. 새 쓰담/간식 입력 전에 만료된 반응을 정리하므로 브라우저가 종료 콜백을 늦게 실행해도 이전 쓰담을 다시 예약하지 않습니다. 진행 중인 반응이 있으면 UI 비활성화와 별도로 reducer에서도 쓰담·간식을 거절합니다. 종료 경계부터 다음 행동을 인정합니다.

삭제 실패 후 재시도는 삭제를 수행합니다. 그 뒤 새 쓰담을 요청하면 기존 기록에 대한 새 저장 요청이 이전 실패한 삭제 요청을 대체하며, 이후 재시도가 갑자기 삭제를 수행하지 않습니다. 성공 시 재시도 대상을 해제합니다.

`PetRepository`는 저장 위치를 분리하는 경계입니다. 현재 구현은 게스트 로컬 저장뿐입니다. 로그인 기능을 추가할 때 계정용 서버 구현과 로그인 상태에 따른 선택, 게스트 기록 이전 정책을 별도로 연결합니다.

## 까미 그림 고치기

그림과 동작은 `sprites/`의 TypeScript에 있으므로 고친 뒤 개발 서버에서 바로 확인합니다. 따로 내보내거나 변환할 파일은 없습니다. 칸 단위 그림은 4단위 격자(`CELL`)에 맞추고, 산책처럼 길과 맞물리는 움직임은 프레임마다 정확히 한 칸씩 움직이게 합니다(`walkSprite.test.ts`가 확인).
