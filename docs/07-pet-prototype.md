# 까미 돌봄 프로토타입

개발 서버의 `/pet`에서 체험합니다. 기존 타이머와 별도인 실험 페이지이며,
돌봄 기록은 이 브라우저의 localStorage에 저장합니다. 집중 보상과 서버 저장은 아직 연결하지 않았습니다.

## 동작

기획 결정은 [03-decisions.md](./03-decisions.md), 진행 상태는 [backlog.md](./backlog.md)의 I-020·I-021·I-022·I-023·I-024 및 B-004·B-005에서 관리합니다. 이 문서는 구현·재생성 방법을 설명합니다.

- 실제 Rive 파일에서 `Sleeping` → `Startled` → `Idle` ↔ `Happy` 애니메이션을 재생합니다.
- 처음에는 앞발에 턱을 얹고 엎드려 잡니다. 호흡과 Z 표시가 반복되고, 수면 장면 시작 후 5초가 지나면 바로 대기 자세로 바뀝니다. 클릭·터치·Enter/Space로 깨우면 눈을 뜨고 머리 위 느낌표를 1초 표시한 뒤 대기로 전환합니다. 이때 호흡·Z 표시는 멈추고 추가 입력은 무시합니다. 몸을 일으키는 과정은 없습니다.
- 깨우기는 쓰담으로 세지 않습니다. 대기 상태부터 쓰다듬기를 받습니다. 다시 깨워보기는 누적 횟수를 유지하고 수면부터 다시 시작합니다.
- 강아지 또는 쓰다듬기 버튼 클릭, 터치, 누른 채 이동, 키보드 Enter/Space를 지원합니다.
- 마지막 쓰다듬기 후 2.8초가 지나면 대기로 돌아갑니다.
- 누적 쓰담 횟수는 새로고침·재방문에도 유지합니다. 화면에는 이름·상태·동작·누적 횟수만 남기고, 키보드 안내는 접근성 설명으로 제공합니다.
- 기기의 동작 줄이기 설정에서는 상태별 표정만 보여주고 움직임을 멈춥니다.
- 파일 로드 실패 시 다시 불러오기 버튼을 제공합니다.

## 파일과 데이터 계약

- `src/features/pet/components/PetPlayground.tsx`: React 인터랙션과 페이지 구성
- `src/features/pet/pet.ts`: 시각을 인자로 받는 쓰담 중복 방지·기쁨 종료·초기화 규칙
- `src/features/pet/usePetRive.ts`: 로드·구독·준비 상태와 자세 반영·동작 줄이기 훅. 준비 상태를 돌봄 규칙에 넘기고, 계산된 자세를 Rive에 반영
- `src/features/pet/usePetCare.ts`: 포인터 제스처와 타이머 연결·해제
- `src/features/pet/careStore.ts`: 페이지 수명 동안의 애니메이션 상태와 인정된 쓰담 전달
- `src/features/pet/profile.ts`: 영구 기록의 생성·누적·검증 순수 함수
- `src/features/pet/store.ts`: 복원·저장·재시도·초기화 액션
- `src/features/pet/repository.ts`: 버전 검증과 로컬 저장 구현
- `src/features/pet/components/_room-art.scss`: 방에만 쓰는 도형 치수·팔레트
- `src/i18n/messages/ko.ts`, `en.ts`의 `pet`: 한국어·영어 문구
- `public/rive/kkami-pet.riv`: 실제 브라우저에서 재생하는 Rive 파일
- `src/assets/kkami-pet/scene.rml`: 편집 가능한 Rive 원본
- `scripts/generate-pet-rml.mjs`: 자체 제작 도트 그림과 타임라인을 재생성하는 스크립트
- Artboard: `Kkami`, State machine: `Pet`
- View model: `PetModel`, boolean properties: `isSleeping` (기본 true), `isStartled`·`isHappy` (기본 false), trigger: `sceneReady`

React의 `phase`와 타이머가 boolean을 갱신하면 Rive 상태 머신이 수면·놀람·대기·기쁨을 전환합니다. 자동 깨우기는 `PET_SLEEP_MS`(5초), 수동 깨우기 반응은 `PET_STARTLE_MS`(1000ms)로 관리합니다. `Startled`는 눈과 느낌표가 유지되는 정지 자세이며 React의 타이머가 대기로 전환합니다.

React는 ViewModel 구독을 준비한 뒤 재생합니다. Rive 초기 상태는 수면 그림을 유지하는 100ms 준비 상태를 거쳐 `Sleeping`에 들어가며 `sceneReady` 트리거를 보냅니다. 첫 프레임에서 구독 전에 신호가 사라지는 것을 피하고, 무료 플랜 시작 화면이 끝난 뒤 수면 장면부터 5초를 셉니다. 동작 줄이기에서도 시작 화면은 재생하고 `sceneReady` 이후에 자세를 정지합니다.
캐릭터는 4단위 격자의 사각형으로 제작했고, 12fps의 hold 키프레임을 사용합니다.
Rive 내부 스크립트나 외부 캐릭터 에셋은 사용하지 않습니다.

## 돌봄 기록 저장

`kkamodoro-pet` 키에 `{ version: 1, state: { pet } }` 형식으로 저장합니다. `pet`은 `id`, `createdAt`, `totalPats`, `lastPettedAt`, `updatedAt`만 포함합니다. 날짜는 밀리초 시각이며, 첫 쓰담 전 `lastPettedAt`은 null입니다. 최초 `/pet` 방문에서 기록을 만들고, 인정된 쓰담마다 즉시 저장합니다.

수면·놀람·기쁨, 타이머와 포인터 상태는 저장하지 않습니다. 새로고침은 수면부터 시작하며 다시 깨워보기는 누적 기록을 지우지 않습니다. 설정의 모든 데이터 지우기는 돌봄 기록도 삭제합니다.

앱의 `useHydrateStores`에서 복원하고 `useTabSync`에서 다른 탭 변경을 반영합니다. 쓰기는 최신 기록을 다시 읽어 미저장 쓰담을 합산합니다. Web Locks 지원 환경에서는 읽기·쓰기·삭제를 같은 잠금으로 직렬화합니다. 미지원 환경에서는 쓰기 직전 다시 읽지만 탭들이 정확히 동시에 쓰는 경우 합산을 보장하지 못합니다.

저장 오류는 메모리의 기록과 미저장 횟수를 유지하고 짧은 안내와 재시도만 표시합니다. 새로고침하면 미저장 기록은 사라질 수 있습니다. 손상된 값이나 더 높은 버전은 자동으로 덮어쓰지 않습니다. v1이 최초 포맷이며 이후 마이그레이션은 `decodePet`에 추가합니다.

미저장 횟수(`pendingPats`)와 재시도 대상(`retryOperation`: save/clear/null)을 별도로 관리합니다. 첫 읽기·저장 실패로 임시 ID가 생겼어도 복원 시 미저장 쓰담을 한 번 합산합니다. 반면 이미 확인한 ID가 다른 탭에서 삭제·교체되면 옛 미저장 쓰담을 버립니다. 단순 복원은 대기 중인 저장/삭제를 성공으로 처리하지 않습니다.

삭제 실패 후 재시도는 삭제를 수행합니다. 그 뒤 새 쓰담을 요청하면 기존 기록에 대한 새 저장 요청이 이전 실패한 삭제 요청을 대체하며, 이후 재시도가 갑자기 삭제를 수행하지 않습니다. 성공 시 재시도 대상을 해제합니다.

`PetRepository`는 저장 위치를 분리하는 경계입니다. 현재 구현은 게스트 로컬 저장뿐입니다. 로그인 기능을 추가할 때 계정용 서버 구현과 로그인 상태에 따른 선택, 게스트 기록 이전 정책을 별도로 연결합니다.

## Rive 에셋 다시 만들기

공식 Rive CLI 1.9.2로 제작·검증했습니다. CLI가 설치되어 있고 로그인되어 있어야
`.riv`를 내보낼 수 있습니다. `--publish=local`은 파일 내보내기이며 웹사이트를 공개하지 않습니다.

```sh
node scripts/generate-pet-rml.mjs
rive src/assets/kkami-pet --verify
rive inspect src/assets/kkami-pet --summary
rive src/assets/kkami-pet --publish=local --output-dir=../../../public/rive
```

원본 RML을 직접 수정하면 생성 스크립트 재실행 시 덮어써지므로, 반복적인 변경은
생성 스크립트에도 반영합니다. 스크립트의 `ID`는 RML의 고정 식별자 목록이며 숫자는 유지하고 이름으로 참조합니다. 구조만 리팩토링할 때는 생성 전후 RML의 바이트 동일성도 확인합니다. 무료 Rive Workspace에서 내보낸 현재 파일에는
Rive 시작 스플래시가 포함되어 있습니다.

`npm run dev`와 `npm run build`는 `scripts/copy-rive-runtime.mjs`로 설치된
`@rive-app/webgl2`와 같은 버전의 WASM을 `public/rive/rive.wasm`에 복사합니다.
이 생성 파일은 Git에서 제외하며, 브라우저는 외부 CDN 없이 로컬 파일을 사용합니다.
개발 서버가 이미 켜진 상태에서 처음 추가했다면 복사 스크립트를 한 번 실행합니다.

## 검증

Node.js 22.12 이상에서 `npm run test:run`, `npm run lint`, `npm run format:check`, `npm run build`를 실행합니다. 브라우저에서는 수면 → 수동 깨우기(느낌표 1초)/자동 깨우기(즉시) → 대기 → 클릭·드래그·Enter/Space → 기쁨 → 자동 대기 복귀, 깨우기 횟수 제외·재시작, 모바일 화면과 언어 전환을 확인합니다. 저장 검증에는 새로고침 후 누적 복원, 다시 깨워보기의 기록 유지, 두 탭 동기화, 저장 실패·손상·미래 버전 보호와 전체 초기화를 포함합니다.

알려진 문제: 새로고침 시 방 배경이 잠깐 노출되는 현상은 B-003으로 별도 추적합니다. 말풍선과 Rive 시작 화면의 레이어 순서는 수정했으며, 전체 로딩 표시 전환은 아직 개선 전입니다.
