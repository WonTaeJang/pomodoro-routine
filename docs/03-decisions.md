# 결정 기록

개발하면서 내린 결정과 그 이유를 모아두는 문서입니다. 결정이 바뀌면 기존 내용을 고치고 "변경 이력"에 남깁니다.

## 결정됨

### 플랫폼: 웹 (2026-11-07)
- **이유**: 가장 빠르게 만들어 바로 쓸 수 있고, 스토어 비용과 심사가 없음.
- **검토했던 대안**: 처음부터 앱(Expo, Flutter, 네이티브). 앱은 화면이 꺼져도 서버 없이 정시에 알림이 울리는 장점이 있지만, 스토어 비용(Apple 연 $99, Google 1회 $25), 심사, Google Play 신규 계정의 비공개 테스트(테스터 12명, 14일) 부담이 있음.
- **나중에 앱이 필요해지면**: 웹 코드를 Capacitor로 앱으로 포장하고 로컬 알림을 추가.

### 휴대폰 지원: 반응형 + 화면 꺼짐 방지 (2026-11-07)
- 휴대폰 화면 대응은 **반응형 디자인(CSS)** 으로 함. PWA와는 별개.
- 휴대폰은 화면이 꺼지거나 다른 앱으로 넘어가면 웹페이지 실행을 멈춤 → 종료 알림이 제때 안 울릴 수 있음. 그래서 MVP는 "화면을 켜둔 채로 쓰는" 경우를 기본으로 보고, 타이머 진행 중 **Screen Wake Lock**으로 화면 꺼짐을 막음.
- 남은 시간은 종료 시각 기준으로 계산하므로 다시 돌아오면 정확하게 보임.

### PWA: v1.5에서 적용 (2026-11-07)
- 얻는 것: 홈 화면 설치, 주소창 없는 앱 화면, 오프라인 실행, **iPhone 알림**(iOS는 홈 화면에 설치한 웹앱에만 알림 허용, iOS 16.4 이상).
- PWA로도 화면 꺼진 상태의 정시 알림은 해결되지 않음. 해결하려면 서버 푸시가 필요 → 검토 대상(v3 이후).

### 계정: 로그인 없음, 브라우저 저장 (2026-11-07) → 로그인 추가 (2026-11-08, 2026-11-10)
- 설정, 할 일, 기록은 localStorage에 저장. 참고 사이트와 같은 방식으로 진입 장벽을 없앰.
- 2026-11-08: 로그인과 여러 기기 동기화를 개발하기로 함. 순서는 UI 개선, 캘린더, 집중 음악, 배포 다음 (02-mvp-scope.md "다음 개발 순서").
  - 고정된 HTTPS 주소가 있어야 로그인 서비스를 실제로 연결할 수 있어서 배포 뒤에 함.
  - 로그인 방법, 서비스(Supabase / Firebase 등), 기존 브라우저 데이터 옮기기는 시작할 때 결정. 로그인 없이 쓰는 방식은 유지하는 쪽으로 검토.
- 2026-11-10: **로그인 자체부터** 만듦. 할 일·기록·설정·돌봄 등 지금 기능과는 아직 연결하지 않음 (로그인해도 모든 기록은 이 브라우저에만).
  - **서비스:** Supabase Auth. **방법:** 구글 로그인 먼저, 카카오는 다음. 로그인 없이 쓰는 방식은 그대로.
  - **카카오 로그인 (2026-11-13, I-014):** 구글과 같은 흐름(카카오 → Supabase → `/auth/callback`). 동의항목은 닉네임·프로필 사진, 이메일은 **선택 동의**. Supabase가 카카오에 이메일(`account_email`)을 항상 같이 요청해서, 이메일 동의항목이 없으면 KOE205로 로그인이 막힘 → 카카오 앱을 개인 개발자 비즈 앱으로 바꾸고(본인인증, 비용 없음) 이메일을 선택 동의로 켬. 이메일을 빼고 동의할 수 있으므로 Supabase의 "Allow users without an email"은 켜 둠. 이메일이 없는 카카오 계정은 구글 계정과 이어지지 않아 기록이 따로 쌓임. 앱 아이콘은 헤더와 같은 발바닥(`design/app-icon/`, 비즈 앱 전환에 필요). 개인정보처리방침에 이메일 수집 적기(I-028). 로그인 버튼은 카카오 디자인 가이드의 색(노란 바탕 #FEE500, 85% 검정 글자), 버튼 앞 로고(구글 4색 G, 카카오 말풍선)는 공개 준비(I-028) 때 붙임(2026-11-14).
  - 개발 중에는 Supabase에 `http://localhost:3000/**`를 돌아올 주소로 허용해 내 컴퓨터에서 바로 시험함 (배포 전에도 가능). 배포하면 실제 주소를 추가.
  - **로그인 정보는 이 브라우저(localStorage, `kkamodoro-auth`)에 둠.** 앱이 모두 브라우저에서 동작하고 서버에서 로그인 정보를 읽을 일이 없어서, 쿠키 방식(`@supabase/ssr`)과 `proxy.ts`는 쓰지 않음. 나중에 서버 화면에서 로그인 정보가 필요해지면 바꿈.
  - **흐름:** 로그인 화면(`/login`) → 구글 → Supabase → 돌아오는 화면(`/auth/callback`)이 주소의 code로 로그인을 마침 (PKCE). 돌아갈 주소(`next`)는 이 사이트 안의 주소만 허용.
  - **프로필(`/profile`):** 사진, 닉네임, 이메일, 로그인 방법 배지("Google로 로그인"), 가입한 날, 맨 아래 구분선 밑에 로그아웃 | 회원 탈퇴. 닉네임은 옆 연필을 누르면 그 자리에서 고치고(20자까지, 비우면 로그인한 계정의 이름) Supabase 사용자 정보(`user_metadata.nickname`)에 저장. 따로 데이터베이스 표는 아직 없음. 로그아웃은 확인 창에서 이 브라우저의 할 일·기록·타이머가 지워진다고 알린 뒤 함 (2026-11-13, I-044).
  - ☰ 메뉴 맨 위에 "로그인", 로그인하면 프로필 사진과 닉네임(→ 내 프로필).
  - Supabase 주소·공개 키(`.env.local`)가 없으면 로그인 메뉴만 숨기고 나머지는 그대로. 로그인 관련 화면은 검색에 나오지 않게 함.
  - 로그아웃은 프로필에서. ("모든 데이터 지우기"는 2026-11-11에 없앰)
- 2026-11-11: **계정에 기록 저장 시작 (백로그 I-027).** 할 일·집중 기록·설정을 Supabase 표에 저장 (돌봄 기록은 나중에). 설계는 아래 [계정 동기화 확정 설계](#account-sync-design), 표는 `supabase/sync-tables.sql`.
  - **따로 서버(API)를 두지 않고 브라우저에서 Supabase로 바로 읽고 씀.** 표마다 RLS로 "로그인한 본인 행만" 허용해서 공개 키로도 안전함. 로그인 정보가 브라우저에만 있는 지금 구조와 맞음.
  - 로그인하지 않으면 지금처럼 브라우저에만 저장. 로그인한 동안에도 브라우저 저장이 기준이고(인터넷이 끊겨도 그대로 씀), 계정과는 뒤에서 맞춤.
  - **집중 기록 (먼저 구현):** 로그인하면 서버 기록을 받아(1,000줄씩) 합치고, 이 브라우저에만 있는 기록을 올림. 기록이 생기면 바로 올리고, 실패하면 인터넷이 다시 연결되거나 탭으로 돌아올 때 다시 올림. 탭으로 돌아오면 5분에 한 번까지 서버 기록을 다시 받음 (다른 기기의 기록). 같은 기록(종류 + 끝난 시각)은 서버가 건너뜀.
  - **할 일 (2026-11-12):** 이 브라우저에 "서버와 같다고 확인한 할 일의 모양"을 기억해 둠(`kkamodoro-account-sync`, 계정별). 모양이 달라진 할 일은 올리고(덮어씀), 기억에는 있는데 목록에 없으면 지운 것으로 보고 서버에 지운 표시(`deleted_at`)만 함. 받을 때는 마지막으로 받은 고친 시각보다 1분 앞부터 받음(서버 시각이 트랜잭션 시작 기준이라 늦게 끝난 저장을 놓치지 않게). 받은 할 일을 이 브라우저에서도 고쳤으면 이 브라우저 쪽을 남기고 바로 올림. 고친 뒤 0.8초 모았다가 올림.
  - **설정 (2026-11-12):** 기기끼리 맞출 8개 항목 + 지금 집중할 할 일. 이 브라우저에서 고치지 않았으면 서버 설정을 따르고, 고쳤으면 올림. **이 브라우저에서 처음 맞출 때 서버에 설정이 있으면 서버 설정을 따름** (새 기기에서 로그인하면 기본 설정이 계정 설정을 덮지 않게). 받은 값은 항목별로 검사해서 범위 밖이면 이 브라우저 값을 씀. 할 일을 먼저 맞춘 뒤 설정을 맞춤 (지금 집중할 할 일이 있어야 고를 수 있음).

### 계정 동기화 확정 설계 (I-027)

아래는 목표 동작입니다. 구현 완료 범위와 남은 검증은 [백로그 I-027](./backlog.md)에서 관리합니다. 2026-11-12 백로그에 있던 확정 설계를 이곳으로 이동했습니다.

- **확정한 설계 (2026-11-11, 사용자 결정):**
  - **범위:** 할 일, 집중 기록, 설정만. **돌봄 기록은 이번에 제외** (나중에 따로).
  - **구분 기준:** Supabase 사용자 UUID(`auth.uid()`). 이메일·로그인 방식은 쓰지 않아서 카카오 로그인(I-014)을 나중에 붙여도 DB는 그대로.
  - **표 3개** (SQL: `supabase/sync-tables.sql`. 사용자가 Supabase SQL Editor에서 직접 실행):
    - `tasks`: 앱의 `Task`와 1:1. 기본 키 `(user_id, id)` (같은 브라우저에서 계정을 바꿔도 충돌하지 않게). `order`는 `sort_order`. 지울 때는 행을 없애지 않고 `deleted_at`만 채움 (다른 기기가 다시 올리지 않게).
    - `sessions`: 앱의 `CompletedSession`과 1:1. 기본 키 `(user_id, mode, ended_at)` (앱의 중복 기준 `mode:endedAt`과 같음). 추가만 하고 고치거나 지우지 않음. `task_id`는 외래 키 없음 (할 일을 지워도 제목이 남게 `task_title` 유지).
    - `user_settings`: 사용자마다 한 줄. `settings`(jsonb) + `active_task_id`.
  - **서버에 올리는 설정:** `focusMinutes`, `shortBreakMinutes`, `longBreakMinutes`, `longBreakInterval`, `autoStartBreaks`, `autoStartFocus`, `focusSound`, `certificateShowTasks`.
  - **브라우저에만 두는 설정:** `soundEnabled`, `soundVolume`, `focusSoundVolume`, `notificationsEnabled`, `ringEffects`, `keepScreenOn`, `testDurationSeconds`, 테마, 언어, 첫 방문 안내 여부.
  - **충돌:** 나중에 고친 쪽이 이김. `updated_at`은 서버가 찍음 (DB 트리거. 기기 시계를 믿지 않음).
  - **올리지 않는 것:** 진행 중인 타이머 상태 (기기마다 따로).
  - **보안:** 표마다 RLS, "본인 행만". 로그인한 사람만 읽기·추가·수정(기록은 읽기·추가만). 회원 탈퇴 때는 `on delete cascade`로 함께 지워짐 (I-028).
  - **"모든 데이터 지우기" 기능은 없앰.** 서버에서만 지우면 다른 기기가 다시 올리는 문제가 있어 기능 자체를 뺌. "설정 초기화"는 남김. (`DataSection`, `resetData.ts`의 `resetAllData`, 관련 문구·문서 정리)
  - **로그아웃:** 이 브라우저의 할 일·기록·타이머(진행 중이던 세션과 사이클)와 계정 맞추기 기억(`kkamodoro-account-sync`)을 지움. 설정·테마·언어·첫 방문 안내는 브라우저 설정이라 그대로 두고, 돌봄 기록은 나중에 계정과 연동할 예정이라 남김. 아직 계정에 올리지 못한 변경이 있어도 묻지 않고 지움 (2026-11-12 사용자 결정). 다른 탭에서 로그아웃해도 같음. 로그아웃 확인 창에서 지워진다는 안내를 둠.
  - **로그인 전 데이터 합치기 (2026-11-13 사용자 결정, 지금 방식 유지):** 로그인하면 로그인 전에 이 브라우저에 쌓인 집중 기록·할 일을 묻지 않고 계정에 합침. 집중 기록은 모드 + 끝난 시각이 같을 때만 같은 기록으로 보므로, 다른 기기와 시간이 겹치는 기록(예: 로그인한 PC와 로그아웃한 노트북에서 동시에 집중)도 둘 다 남아 그날 집중 시간·🐾가 늘어날 수 있음. 로그인한 기기 두 대에서 동시에 타이머를 돌려도 같음(타이머는 기기끼리 맞추지 않음). 공용 PC에서 다른 사람이 로그인 없이 쓴 기록이 섞이거나, 같은 이름의 할 일이 두 개 보일 수 있음.
    - 흔치 않은 경우라 그대로 둠. 문제가 되면 로그인할 때 "로그인 전 기록 N개, 할 일 M개를 계정에 합칠까요? [합치기] [버리기]"를 묻고, 합칠 때 계정 기록과 시간이 겹치는 기록은 빼는 방식을 검토.
  - **회원 탈퇴 (2026-11-13, 백로그 I-043):** 프로필의 "회원 탈퇴" → 확인 팝업에서 한 번 더 누르면 계정을 지움. 서버 DB 함수 `delete_my_account()`(`supabase/delete-account.sql`)가 로그인한 본인(`auth.uid()`)의 계정만 지우고, 세 표의 본인 행은 `on delete cascade`로 함께 지워짐. secret 키를 브라우저에 넣지 않으려고 관리자 API(Edge Function) 대신 이 방식을 씀. 탈퇴하면 로그아웃과 같이 이 브라우저의 할 일·기록·타이머를 지우고 타이머 화면으로. 같은 구글 계정으로 다시 로그인하면 새 빈 계정.
  - **처음 로그인할 때:** 이 브라우저에 쌓인 할 일·기록을 계정으로 올려 합침 (기록은 기본 키로 중복 없이, 할 일은 그대로 더해짐).
- **알고 넘어가는 한계:** 두 기기에서 같은 할 일로 동시에 집중하면 `completed_pomodoros`가 1 빠질 수 있음. 설정은 한 덩어리로 덮어씀.

### 기술 스택: Next.js + TypeScript (2026-11-07)
- **이유**: 나중에 로그인, 웹 푸시, 함께 집중하기 같은 서버 기능을 같은 프로젝트 안에서 만들 수 있고, 공개 서비스일 때 검색 노출과 Vercel 배포에 유리함.
- **주의**: 타이머, 할 일 화면은 클라이언트 컴포넌트(`"use client"`)로 만듦. localStorage 값(설정, 테마)이 첫 화면에서 서버 렌더링과 달라 깜빡이는 문제(hydration 불일치)를 처음부터 처리함.
- **검토했던 대안**: React + Vite. MVP만 보면 더 가볍지만, 서버 기능을 붙일 때 별도 서버나 BaaS가 필요함.

### 타이머 세부 규칙 (2026-11-07)
- 남은 시간은 "끝나는 시각 - 현재 시각"으로 계산. 다른 탭에 있거나 새로고침해도 정확함.
- 집중 완료 → 짧은 휴식. 이번 사이클 집중이 긴 휴식 주기(기본 4)에 닿으면 긴 휴식. 긴 휴식이 끝나거나 건너뛰면 사이클 처음부터.
- **리셋, 건너뛰기, 모드 탭 전환은 완료로 세지 않음.** 진행 중이거나 멈춘 세션이 있을 때 모드 탭을 누르면 확인 팝업을 띄움.
- 자동 시작이 켜져 있으면 완료 팝업에서 **5초를 센 뒤** 다음 세션이 시작됨 (2026-11-08, 백로그 I-002). 처음에는 이전 세션이 끝난 시각부터 바로 이어서 진행했음.
  - 5초는 팝업이 실제로 보인 순간부터. 다른 탭에 있거나 자리를 비우면 돌아올 때까지 기다림. "지금 시작" / "취소"(X·Esc도 취소).
  - **사이클을 마친 순간(긴 휴식 차례)은 자동 시작하지 않음** (백로그 I-004). 수료증과 완료 팝업을 먼저 보게 함.
- 설정 창, 수료증 창을 보는 중에 세션이 끝나면 완료 팝업은 그 창을 닫을 때까지 기다렸다가 뜸 (백로그 I-003). 브라우저 팝업은 나중에 연 것이 항상 위에 그려져서, 보고 있던 창을 덮지 않도록.
- **자리를 비운 사이 끝난 경우**: 끝난 세션 1개만 완료로 기록. 다음 세션까지 이미 끝났을 시간이면 시작 전 상태로 둠 (자리를 비운 동안 뽀모도로가 저절로 쌓이지 않게).
- 설정을 바꾸면 시작 전 세션에만 바로 반영. 진행 중인 세션은 그대로.
- 끝까지 마친 세션은 모두(휴식 포함) 날짜와 함께 기록. "오늘"은 기기 시간 기준 자정부터.

### 할 일 규칙 (2026-11-07)
- 첫 할 일은 자동으로 "집중 중"이 됨. 다른 할 일은 "선택" 버튼으로 바꿈.
- 집중을 끝까지 마치면 그때 선택돼 있던 할 일에 🐾 +1. 세션 기록에도 할 일을 함께 저장(수료증, 통계용).
- 집중 중인 할 일을 완료하거나 지우면 남은 할 일 중 첫 번째가 자동 선택.
- 예상 뽀모도로 수는 1~20, 제목은 100자까지. 완료한 할 일은 목록 아래로.
- 할 일마다 **순서(order), 등록 시각(createdAt), 완료 시각(completedAt)** 을 저장. 완료를 취소하면 완료 시각은 지움. 순서는 추가할 때 맨 아래 번호가 붙고, 끌어서 다른 할 일 자리로 옮길 수 있음(같은 묶음 안에서만, 아래 "할 일 순서 바꾸기").
- 저장 형식이 바뀌면 `version`을 올리고 예전 데이터를 변환(migrate). 할 일은 v2부터 순서, 완료 시각 포함. 예전에 완료한 할 일의 완료 시각은 알 수 없어 비워 둠. v3부터 목록에서 숨긴 시각(archivedAt) 포함.
- "완료한 할 일 정리"는 완료한 할 일을 **지우지 않고 목록에서만 숨김**(archivedAt). 캘린더에는 계속 보임. 숨긴 할 일도 완료를 취소하면 다시 보임. 휴지통 버튼은 그대로 진짜 삭제. (2026-11-08)

### 집중 후 할 일 완료 확인 (2026-11-07)

### 시간 표시 디자인 (2026-11-07)
- 시간 숫자는 지금처럼 큰 디지털 숫자로 유지. **아날로그 시계와 시계 모양 선택 기능은 만들지 않음.**
- 대신 까미 사진 둘레에 **원형 진행 띠**를 둠. 12시 방향에서 시작해 시계 방향으로 지난 시간만큼 흐려지고, 남은 부분은 모드 색으로 보임. 장식이므로 화면 낭독기에는 숨기고 남은 시간은 숫자로 전달.
- **띠 효과**: 집중을 방해하지 않도록 처음에는 차분하게, 끝에 가까울수록 살아나게 함.
  - 10%마다 발자국 도장 하나 (10%~90%, 9개): 발자국 수만 봐도 "몇 % 했는지" 알 수 있게. 까미가 원을 따라 걷는 방향으로 회전. 100%는 완료 효과가 대신함
  - 마지막 1분(세션이 5분보다 짧으면 전체의 20%): 띠 글로우 + 지금 위치에 빛나는 점
  - 집중 완료: 띠가 퍼지고 발자국·색종이가 터진 뒤 1초 후 완료 팝업. 한 사이클 완료면 더 크게
  - 마지막 10초 박동 효과는 넣지 않음
  - 움직임 줄이기 설정이면 움직임 없이 빛만 표시. 설정 화면에서 띠 효과를 끌 수 있음 (끄면 띠만 줄어들고 발자국, 빛, 완료 축하가 없음)

### 디자인 토큰과 공통 컴포넌트 (2026-11-07)
- 색, 간격, 글자, 모양, 움직임, 크기 값을 `src/styles/tokens/`의 CSS 변수로 모아 관리. 화면 코드에는 직접 값을 쓰지 않음 (한 컴포넌트 전용 값은 이름 붙인 Sass 변수로).
- 반복되던 카드와 배지를 `Card`, `Badge` 공통 컴포넌트로, 할 일의 🐾 개수 표시를 `PawCount`로 묶음. 커진 `TimerPanel`은 모드 탭, 버튼, 사이클 진행, 타이머 훅으로 나눔.
- 리팩터링 전후 주요 화면 8개를 고정된 시계와 데이터로 찍어 픽셀 비교 → 차이 0%.
- 상세 규칙은 [06-design-system.md](./06-design-system.md).

### 알림 소리와 브라우저 알림 (2026-11-07)
- **소리**: 오디오 파일 없이 Web Audio API로 종소리를 만듦. 집중 끝(도-미-솔), 휴식 끝(솔-도), 사이클 완료(도-미-솔-도 팡파레).
- **제때 울리게**: 시작할 때 끝나는 시각에 맞춰 소리를 **미리 예약**(오디오 시계는 숨긴 탭에서도 느려지지 않음). 끝나는 시각에는 반복 타이머가 아닌 **한 번만 실행되는 타이머**로 세션을 넘김(숨긴 탭에서 반복 타이머는 1분 단위로 늦어질 수 있음). 예약이 어긋났으면 세션이 끝난 걸 확인한 순간 울리고, 같은 세션에 두 번 울리지 않음.
- 일시정지, 리셋, 건너뛰기, 모드 변경 시 아직 울리지 않은 예약은 취소. 이미 울리기 시작한 소리는 끝까지 둠.
- **브라우저 규칙**: 소리는 사용자가 누른 뒤에만 낼 수 있어서 시작 버튼(또는 화면 아무 곳)을 누를 때 오디오를 깨움. 알림 권한은 **처음 시작 버튼을 누를 때 한 번** 물어봄.
- **브라우저 알림은 다른 탭에 있을 때만** 띄움. 화면을 보고 있으면 완료 팝업으로 충분.
- 알려진 제약
  - 안드로이드 크롬은 서비스 워커로만 알림을 띄울 수 있어 지금은 알림이 안 뜸 → v1.5 PWA에서 해결
  - iPhone은 무음 모드에서 웹 소리가 안 날 수 있음. 무음을 무시하는 설정(Audio Session `playback`)은 사용자가 듣던 음악을 멈출 수 있어 쓰지 않음
  - 화면이 꺼진 휴대폰에서는 웹페이지가 멈춰 제때 알릴 수 없음 (서버 푸시 필요, v3 검토)
- 설정 값(소리 켜기, 볼륨 0.7, 알림 켜기)은 저장해 두었고, 바꾸는 화면은 4단계에서 만듦.
- 예약·취소·중복 방지 규칙은 브라우저 기능과 분리한 `scheduler.ts`에 두고 단위 테스트로 검증. 화면 쪽 훅(`useAlerts`)은 연결만 함.

### 설정 화면 (2026-11-07)
- 헤더의 설정 버튼으로 여는 팝업. 따로 저장 버튼 없이 **바꾸는 즉시 저장, 적용**.
- 묶음: 타이머(시간, 긴 휴식 주기, 자동 시작) / 알림(소리, 소리 크기와 미리 듣기, 브라우저 알림) / 화면(테마, 띠 효과) / 데이터(설정 되돌리기).
- 시간은 숫자 입력칸 대신 − 값 + 버튼(Stepper)으로. 잘못된 값을 넣을 일이 없고 휴대폰에서도 누르기 쉬움. 집중, 긴 휴식은 5분 단위.
- 바꾼 시간은 **시작 전 세션에만 바로 적용**. 진행 중이면 "다음 세션부터 적용" 안내를 보여줌.
- 브라우저 알림이 차단돼 있으면 스위치를 꺼진 상태로 막고, 사이트 설정에서 허용하라고 안내.
- 소리를 켜는 순간 오디오를 깨움 (사용자가 누른 순간에만 소리를 낼 수 있음).
- **설정 되돌리기**: 시간, 알림, 화면 설정(테마 포함)만 처음 값으로. 할 일과 기록은 그대로.
- **모든 데이터 지우기는 없앰 (2026-11-11, 백로그 I-027)**: 계정에 기록을 저장하면, 한 기기에서 지워도 예전 기록을 가진 다른 기기가 다시 올려 버림. 기능 자체를 빼고 "설정 되돌리기"만 남김. 브라우저에만 저장하는 사람은 브라우저의 사이트 데이터 지우기로 지울 수 있음.
- 개발용 5초 테스트 모드는 주소로 켠 것이라 되돌리기·지우기 뒤에도 유지.

### 다음 세션(⏭) 버튼 확인 (2026-11-07)
- ⏭는 사이클 순서상 다음 세션으로 바로 넘어가는 버튼 (휴식 건너뛰고 바로 집중, 급한 일로 집중 일찍 접기 등).
- 시작했거나 멈춘 **집중**을 건너뛰면 그 시간이 기록 없이 사라지므로, 모드 탭처럼 한 번 확인함.
- 휴식, 시작 전 세션은 잃을 게 없어서 확인 없이 바로 넘어감.
- 확인 팝업(건너뛰기, 모드 탭 전환)을 띄운 사이 세션이 끝나거나 바뀌면 팝업을 자동으로 닫음. 그대로 확인하면 엉뚱한 세션(예: 방금 시작된 휴식)이 건너뛰어지기 때문 (`useSessionState`).

### 단축키, 화면 꺼짐 방지 (5단계, 2026-11-07 확정)
- **단축키**: `Space` 시작/일시정지, `R` 리셋, `N` 다음 세션, `S` 설정. 버튼과 똑같이 동작 (시작은 `startSession()`, `N`은 진행 중인 집중이면 확인).
  - 입력칸에 쓰는 중, Ctrl·⌘·Alt·Shift와 함께 누를 때, 팝업이 열려 있을 때, 키를 꾹 누르고 있을 때는 동작하지 않음.
  - `Space`와 포커스: 마우스로 ⏭ 등을 누르면 포커스가 그 버튼에 남아서, 브라우저 기본 동작대로면 `Space`가 그 버튼을 한 번 더 누름 (⏭로 휴식을 건너뛴 뒤 `Space`로 시작하려다 또 건너뜀). 그래서 **마우스로 생긴 포커스에서는 `Space` = 시작/일시정지**, **Tab·방향키로 골라 온 버튼·체크박스에서만 `Space`를 그 요소에 맡김** (키보드 사용자 접근성). 글자 단축키는 어디서든 동작.
  - 다른 기능이 이미 쓴 키는 단축키로 처리하지 않음. 예: 마우스로 할 일 손잡이를 누른 뒤 `Space` → 키보드로 옮기기만 시작되고 타이머는 그대로.
  - CSS `:focus-visible`은 키를 누르는 순간 키보드 쪽으로 바뀌어서 이 구분에 쓸 수 없음 → 포커스를 옮긴 수단을 직접 기록 (`focusSource.ts`).
  - 키보드가 없는 기기(터치만 되는 휴대폰)에서는 설정 창의 단축키 목록을 숨김.
  - 한글 자판 상태에서도 되도록 글자가 아닌 키 위치(`event.code`)로 판단.
  - 안내: 버튼에 마우스를 올리면 "시작 (Space)"처럼 보이고, 설정 창에 단축키 목록.
- **리셋 확인**: 리셋 버튼과 `R` 모두, 시작했거나 멈춘 **집중**일 때만 확인 팝업 (⏭와 같은 규칙).
- **화면 꺼짐 방지**(Screen Wake Lock): 타이머가 도는 동안(집중, 휴식 모두) 화면을 켜 둠. 멈추면 바로 풀고, 다른 탭에 갔다 돌아오면 다시 요청.
  - 설정 "화면" 묶음에 스위치, **기본 켜짐**. 지원하지 않는 브라우저면 스위치를 막고 안내.
  - PC는 화면 꺼짐·잠금·노트북 절전을 막고, 휴대폰은 화면이 꺼져 페이지가 멈추는 걸 막아 알림이 제때 울리게 함.
  - 지원: 크롬·엣지 84+, 사파리 16.4+, 파이어폭스 126+, 아이폰 iOS 18.4+. 지원하지 않으면 조용히 아무것도 안 함. 전원 버튼으로 직접 끄는 건 막을 수 없음.

### 까미 마스코트, 수료증 (6단계, 2026-11-07)
- **마스코트**: 까미 사진 대신 까미(검은 푸들)를 바탕으로 직접 그린 SVG 마스코트를 씀. 특징: 검은 곱슬털, 둥글게 부푼 머리와 귀, 반짝이는 까만 눈, 분홍 혀, 파란 체크 턱받이와 데이지.
  - A 기본(턱받이) / B 수료증용(학사모 + 발자국 메달) / C 단순 아이콘(로고·파비콘 후보) 세 가지. 시안 확정.
- **수료증 이미지**: 인스타 스토리 크기 1080×1920 하나만. 브라우저 캔버스에 직접 그려 PNG로 만듦 (라이브러리, 서버 없이).
  - 디자인: **축하 카드** (토마토→분홍 그라데이션 배경 + 색종이, 흰 카드 위로 까미 B가 튀어나옴, 빨간 "까미 인증" 도장).
  - **까미 사진으로 바꿈 (2026-11-11, 백로그 I-026)**: 학사모 마스코트(B) 대신 실제 까미 사진을 **동그랗게 잘라 빨간 테두리와 밝은 띠**를 두르고, 카드 위로 반쯤 걸치게 둠. 타이머 화면의 원형 사진과 모양을 맞춤. 배경을 지운 사진(누끼)은 까만 곱슬털 가장자리가 거칠어지기 쉬워 원형으로 정함. 학사모는 넣지 않음.
  - 스토리 위아래 약 250px는 인스타 화면에 가려지므로 중요한 내용은 그 안쪽에 둠.
  - 이름은 넣지 않음. 나중에 로그인 계정을 만들면 그때 이름을 넣는 걸 검토.
  - 이번 사이클에 한 할 일은 최대 3개 표시하고, 수료증 팝업에서 숨길 수 있게 함.
  - 공유: 휴대폰은 공유 창(Web Share), PC나 미지원 브라우저는 PNG 저장. 아이폰 사파리는 누른 순간에만 공유 창을 열 수 있어서 팝업이 열릴 때 이미지를 미리 만들어 둠.
- **수료증 내용**
  - 상단: "한 사이클 완료!" / 번호와 날짜: "제 12호 · 2026.11.07" (번호 = 지금까지 완료한 사이클 수)
  - 제목: **까모도로 수료증**
  - 본문(한 가지 문구 고정): "25분 집중을 4번 해내었기에 이 수료증을 드립니다." (25분, 4번은 설정값에 따라 바뀜)
  - 숫자 칸 3개: 이번 사이클 집중 시간 / 뽀모도로 수 / 오늘 완료한 사이클
  - 메달 배지로 나중에 다시 만들면 **가장 최근에 완료한 사이클**의 수료증
  - 칭호(누적 사이클에 따른 이름)는 다음 기능 업데이트에서 추가
  - 할 일이 없거나 숨기면 그 자리에 "오늘도 한 걸음 성장했어요" (할 일 없을 때의 별도 문구는 2026-11-13 I-051에서 뺌)
  - 시간 표기: 1분 미만은 초, 1시간 이상은 "1시간 40분"
- **진입**: "한 사이클 완료!" 팝업의 "수료증 만들기" 버튼, 타이머 아래 "오늘 N사이클 완료" 메달 배지(누르면 열림).
- "할 일 보이기" 선택은 저장해 두고 다음에도 그대로 씀 (설정 되돌리기로 처음 값).
- 그리기 글꼴: 화면과 같은 Pretendard. 대체 글꼴(Arial 기반)이 없는 기기에서도 그릴 수 있게 글꼴 불러오기 실패는 무시.

### 타이머 화면 한 화면에 맞추기 (2026-11-08)
- 화면을 길게 만들던 "지금 할 일" 줄과 사이클 아래 "오늘 N사이클 완료" 배지를 없앰.
  - 지금 할 일 → 상태 문구 자리의 칩 (상태 문구와 할 일 중 하나만, 같은 높이라 바뀌어도 화면이 들썩이지 않음)
  - 오늘 사이클 수 → 헤더의 🏅 숫자 버튼 (헤더의 오늘 기록 배지에서는 사이클 수를 뺌, 겹치지 않게)
- 사진·진행 띠 지름 132~192px, 남은 시간 글자 3.5~7.5rem, 여백을 화면 높이(dvh)에 맞춰 조절. 진행 띠(`ProgressRing`)는 `--ring-display-size`로 크기를 바꿔도 도장 위치, 안쪽 사진 크기가 같은 비율로 따라감.
- 휴대폰에서 할 일을 탭으로 나누는 안은 쓰지 않음. 타이머 카드가 첫 화면에 다 들어가고 할 일은 아래로 스크롤.

### 할 일 순서 바꾸기: dnd-kit (2026-11-08)

- 수정 중인 할 일은 손잡이가 없고 옮길 수 없음.
- "움직임 줄이기" 설정이면 다른 할 일이 미끄러지듯 비켜나는 움직임 없이 바로 자리를 바꿈.

### 캘린더 페이지 (2026-11-08)
- 주소 `/calendar`. 헤더 로고 옆에 "타이머 · 캘린더" 메뉴. 좁은 휴대폰(480px 미만)에서는 로고 글자를 숨기고 발자국만.

- **달력 칸**: 숫자를 넣지 않고 집중 횟수에 따라 색이 진해짐 (1번, 3번, 5번, 8번 이상의 4단계, 아래 범례). 사이클을 마친 날은 🏅. 한 주는 일요일부터. 오늘은 안쪽 테두리, 고른 날은 바깥 테두리.
- **날짜 상세**: PC는 달력 오른쪽, 휴대폰은 달력 아래. 집중 횟수, 집중한 시간, 사이클 수, 그날 마친 사이클의 수료증 버튼, 완료한 할 일, 진행 중이던 할 일.
  - **완료한 할 일** = 그날 완료한 할 일 (집중 없이 완료한 것도).
  - **진행 중이던 할 일** = 그날 집중했지만 그날이 끝날 때까지 완료하지 않은 할 일. 다음 날 끝냈어도 그날은 진행 중으로 보임. "등록만 하고 안 끝난 할 일"은 끝낼 때까지 매일 보여서 쓰지 않음.
- **지난 수료증**: 사이클마다 번호(제 N호)로 다시 만들 수 있음. 숫자 칸 이름은 오늘 마친 사이클이면 "오늘 완료", 지난 사이클이면 "이날 완료".
- **기록에 할 일 제목 저장**: 집중 기록에 할 일 id와 함께 그때 제목(taskTitle)을 남김. 할 일을 지워도 캘린더, 수료증에 제목이 남음. 제목이 없는 예전 기록은 지금 남아 있는 할 일에서 제목을 찾음.
- **타이머는 모든 페이지에서 동작**: 시간이 되면 넘기기, 알림, 완료 팝업, 탭 제목, 화면 켜두기를 페이지 공통 틀(`AppShell`)로 옮김. 캘린더를 보는 중에 집중이 끝나도 팝업과 소리가 나옴. 단, Space·R·N 단축키는 타이머 화면에서만 (S 설정은 어디서나).
- 탭 제목은 `metadata`가 아니라 `<head>`에 직접 둠. `metadata`로 두면 페이지를 옮길 때 Next.js가 제목을 되돌려서 남은 시간이 사라짐.

### 관리자 페이지와 VIP (2026-11-14, 백로그 I-015)

### 통계 (2026-11-08)
- **어디에**: 따로 탭이나 페이지를 만들지 않고 캘린더 페이지 맨 위에 "통계" 카드. PC·휴대폰 모두 맨 위 (달력보다 먼저 보이게).
- **연속 일수**: 집중을 1번 이상 마친 날을 셈 (사이클을 다 마치지 않아도 됨). 오늘 아직 집중하지 않았으면 어제까지 이어진 날 수를 보여주고 "오늘 집중하면 N일째"로 안내. 하루를 건너뛰면 0부터. 최고 기록도 함께.
- **최근 7일**: 이번 주(월~일)가 아니라 오늘을 포함한 최근 7일 합계. 그 전 7일과 집중 시간을 비교해 "+N분 / −N분". 월요일에도 숫자가 0으로 떨어지지 않고, 늘 같은 날 수끼리 비교됨.
- **이번 달**: 1일부터 오늘까지 집중 시간과 사이클 수. 달력 위의 "집중 N번 · 사이클 N개"는 보고 있는 달 기준이라 따로 둠.
- **전체**: 큰 숫자는 집중 횟수(🐾와 같은 단위), 아래에 전체 시간과 사이클 수.
- **막대 차트**: 최근 7일 하루 집중 시간(분). 라이브러리(Recharts 등) 없이 CSS로 그림. 화면 낭독기에는 같은 내용을 숨긴 표로 읽어 줌.

### 다국어 (2026-11-08, 백로그 I-013)
- **언어**: 한국어(기본) + 영어. 다른 언어는 사전 파일을 하나 더 만들면 됨.
- **주소는 그대로** (`/en/...`로 나누지 않음). 배포 사이트가 아직 없어 검색 노출보다 단순함을 택함. 나중에 검색 노출이 중요해지면 주소로 나누는 방식(next-intl)으로 옮길 수 있게 같은 사전 형식을 씀.
- **언어 정하기**: ① 직접 고른 언어(`kkamodoro-locale`) → ② 없으면 브라우저 언어 목록에서 한국어·영어 중 먼저 나오는 것 → ③ 둘 다 없으면 영어 (한국어를 쓰지 않는 사람이 영어를 읽을 가능성이 더 높아서). 고르지 않았으면 저장하지 않아서 브라우저 언어를 바꾸면 따라감.
- **바꾸는 곳**: ☰ 메뉴의 "언어"(한국어 / English, 메뉴를 연 채로 바뀜)와 설정 → 화면 → 언어. 언어 이름은 어느 화면에서든 그 언어로 씀. 다른 탭도 함께 바뀜.
- **설정 되돌리기**를 하면 고른 언어도 지워져 브라우저 언어를 따름 (테마와 같음).
- **라이브러리**: use-intl (next-intl의 바탕이 되는 라이브러리, 브라우저에서만 씀). 문구 형식은 ICU(`{count, plural, ...}`)라 영어의 단수·복수를 문구 안에서 처리. 한국어 사전(`src/i18n/messages/ko.ts`)이 기준이고, 영어 사전은 같은 모양이 아니면 타입 오류.
  - 직접 만드는 방식(사전 + 함수)도 검토했지만 단수·복수, 문장 속 굵게·아이콘 넣기를 다시 만들어야 해서 라이브러리를 씀.
- **첫 화면**: 서버는 한국어로 그리고, 브라우저가 다른 언어로 정하면 바로 그 언어로 다시 그림. 그동안 화면을 숨겨서 한국어가 잠깐 보이지 않게 함 (스크립트가 늦어도 2초 뒤에는 보임).
- **화면 밖 글**: 브라우저 알림, 탭 제목, 수료증 이미지도 같은 사전을 씀. 수료증은 영어로 그리면 긴 줄을 자동으로 줄여서 그림.
- **날짜·시간 표기**: `src/lib/date.ts`가 언어를 받아 그 언어 표기로 만듦 ("11월 8일 일요일" / "Sunday, November 8", "1시간 40분" / "1 hr 40 min"). 수료증 날짜는 한국어 "2026.11.08", 영어 "Nov 8, 2026".
- **사용법·첫 방문 안내**: 글이 길어서 사전 대신 언어별 파일(`content.ko.ts`, `content.en.ts`). 섹션 순서와 주소(#tasks 등)는 언어가 달라도 같음.
- **검색·링크 미리보기용 설명**(`description`)은 주소가 하나라 언어별로 나눌 수 없어서 두 언어를 함께 씀 ("까미랑 함께하는 뽀모도로 타이머 · A pomodoro timer with Kkami"). 서버가 그리는 첫 탭 제목은 "까모도로"이고, 화면이 뜨면 언어에 맞게 바뀜.
- 번역하지 않는 것: 할 일 제목처럼 사용자가 쓴 글, 개발용 미리보기 페이지.

### 탭 여러 개 (2026-11-08, 백로그 B-001)
- **다른 탭이 저장하면 이 탭도 다시 불러옴**: 할 일, 기록, 타이머, 설정, 테마. 예전에는 탭마다 따로 들고 있다가 덮어써서 다른 탭에서 추가한 할 일이 사라졌음.
- **같은 세션은 하나로**: 모드와 끝난 시각이 같으면 같은 세션. 두 탭이 같은 집중을 함께 끝내도 기록 1개, 🐾 1번. 저장 형식은 바꾸지 않음 (나중에 서버와 합칠 때도 같은 기준을 쓸 수 있음).
- **소리와 알림은 한 탭에서만**: 알림 소리, 브라우저 알림, 집중 소리는 **마지막으로 누르거나 입력한 탭**에서 남. 처음엔 "마지막으로 본 탭"으로 정했지만, 브라우저는 사용자가 누른 탭에서만 소리를 낼 수 있어서 보기만 한 탭으로 넘기면 소리가 끊김. 그 탭을 닫으면 남은 탭이 맡음.
- **완료 팝업은 모든 탭에**: 한 탭에서 닫거나 다음 세션을 시작하면 다른 탭 팝업도 닫힘. 자동 시작 카운트다운도 함께 셈.
- **바뀐 것이 없으면 저장하지 않음** (B-002): 저장할 내용이 이 탭이 마지막으로 읽거나 쓴 값과 같으면 쓰지 않음 (`tabSafeStorage`). 완료 팝업처럼 저장하지 않는 값만 바뀌었는데, 다른 탭의 새 값을 아직 못 받은 탭이 예전 값으로 덮어쓰던 문제를 막음.
- 팝업을 아직 못 본 자동 시작 대기도 저장함 (다른 탭이 이어받게). 새로고침으로 처음 불러올 때만 버림 (예전과 같음).
- 새 버전 앱을 연 탭이 저장한 값은 예전 탭이 불러오지 않음 (예전 형식으로 덮어쓰지 않게). 배포 뒤 새로고침 안내는 그때 검토.
- 나중에 서버 동기화를 붙여도 같은 브라우저의 탭끼리는 저장소를 함께 쓰고, 로그인 없이 쓰는 경우도 있어서 이 동작은 그대로 필요함.

### 육성 확장 (2026-11-11)
- I-030 먼저 구현: 친밀도 5단계(0·20·60·140·300점). 하루 첫 5회 인정된 쓰담에 +2점씩, 최대 10점. 감소·기능 잠금 없음. 단계는 점수에서 계산.
- 기존 ID·누적 쓰담·시각은 유지. 과거 쓰담은 날짜별 내역이 없으므로 소급하지 않고 친밀도 0점으로 이전. 게스트 로컬 저장, 계정 동기화는 I-027.
- 기기 로컬 날짜별 적립 횟수를 저장해 새로고침·탭·자정 이후 재시도에서도 하루 한도를 공유. 늦게 저장된 쓰담도 해당 날짜의 남은 한도만 적용. 시계 조작 방지는 서버 연동 후 별도 범위.
- 화면은 단계와 작은 진행 막대, 상세 수치는 펼쳐서 확인. 단계 상승 때만 짧은 안내.
- I-037: 집중 보상과 분리해 간식 주기부터 구현. 깨어 있을 때 일일 횟수·재고·집중/휴식 조건 없이 줄 때마다 친밀도 +3점. 쓰담 일일 한도와 별도이며 간식 누적 횟수·점수를 로컬 저장. 수면/놀람 중에는 기존 깨우기 흐름을 유지. 기존 Rive 기쁨 반응과 짧은 간식 말풍선을 사용. 집중 보상·보유 수량·일일 제한은 I-033 후속으로 보류.
- 후속: I-031 단계별 애니메이션, I-032 낮·밤 배경, I-033 집중 완료 간식/휴식 연동, I-034 산책 중 아이템 발견, I-035 보관함·집 배치, I-036 여러 집 스타일. 단계 수는 5개이며 모션은 나중에 추가.

### 간식 모션 추가 결정 (2026-11-11)
- I-038: 뼈고기는 향후 특별 간식 후보로 두고, 현재 기본 간식은 황금빛 갈색 뼈 모양 비스킷. 받기 0.3초·씹기 0.9초·만족 0.6초로 구성한 Rive 전용 모션을 사용한다.
- I-040: 간식 1.8초·쓰담 2.8초 반응 중에는 두 돌봄 버튼·강아지 직접 조작·다시 깨워보기를 비활성화한다. 종료 후 다음 행동을 받으며, 반응 도중 입력은 예약·횟수·친밀도 적립 없이 무시한다. 간식은 인정된 행동마다 +3점이며 일일 제한은 없다. 다시 깨워보기는 기존 누적 기록을 유지한다. 동작 줄이기는 기존 정지 자세 방식을 유지한다.

### 산책 프로토타입 (2026-11-13, I-034)

- 디자인은 [승인 시안](./references/kkami-walk-approved.png)을 기준으로 한다. 수동 재설계는 시안과 차이가 커 폐기한다. 승인 이미지의 윤곽·색 영역을 직접 변환하고, 머리·몸통·주둥이 비율을 임의로 바꾸지 않는다. 그림 전체 교체에 따른 튐을 막기 위해 첫 자세의 머리·몸통은 공통 유지하고 다리의 도트 띠만 움직인다.

- 집의 대기 상태에서 산책하기 → 도트 산책길 1종에서 자동 걷기 → 돌아가기로 집 복귀. 복귀 시 깨어 있는 대기 자세를 유지한다.
- 첫 범위는 시간·횟수·재화·친밀도 조건과 보상 없이 자유 산책. 산책 중 쓰담·간식·수면 재시작은 받지 않고, 기존 돌봄 반응 중에는 산책을 시작하지 않는다.
- 산책 전용 Rive는 진입할 때 불러온다. 로딩 중 빈 장면 노출을 막고 실패 시 재시도·집 복귀를 제공한다. 탭을 보지 않으면 정지, 돌아오면 재생. 동작 줄이기에서는 정적인 산책 자세를 보여준다.
- 산책 상태는 페이지에만 유지한다. 새로고침·이탈은 산책 종료이며 친밀도·돌봄 기록은 유지. 아이템·보관함·확률·보상·뽀모도로 연동은 후속 범위로 남긴다.
