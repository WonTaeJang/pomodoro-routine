# 버그·개선 백로그

사용하면서 발견한 **버그**와 **개선 아이디어**를 모아두는 곳입니다.
접수는 별도 대화에서 받고, 개발 대화에서는 이 파일을 보고 처리합니다.

## 처리 규칙

- 새 항목은 `열림` 상태로 맨 아래에 추가하고, 번호는 이어서 매깁니다. (`B` 버그, `I` 개선)
- 개발 쪽에서 작업을 시작하면 `진행 중`, 끝나면 `완료`로 바꾸고 커밋 해시를 적습니다.
- 하지 않기로 한 항목은 `보류`로 바꾸고 이유를 한 줄 남깁니다.
- 우선순위: `높음`(쓰는 데 지장) · `보통` · `낮음`(있으면 좋음)

### I-001 · 설정 창의 완료 버튼 제거
- 종류: 개선
- 우선순위: 낮음
- 상태: 완료
- 등록일: 2026-11-08
- 화면/기능: 설정 창 하단
- 내용: 설정은 항목을 누르는 즉시 저장·적용되는데, 하단의 **완료** 버튼은 창을 닫기만 한다. 누르기 전에 이미 저장돼 있어서 "완료를 눌러야 저장된다"는 오해를 준다. 완료 버튼을 없앤다.

  2. 설정은 지금처럼 누르는 즉시 저장·적용된다 (동작 변경 없음).
  3. 창은 X 버튼, Esc, 바깥 클릭으로 닫는다 (이미 `Dialog`에 있음).
- 관련 코드:
  - `src/features/settings/components/SettingsDialog.tsx`: `footer={<Button onClick={onClose}>완료</Button>}`를 지우고, 쓰지 않게 되는 `Button` import도 정리한다. `Dialog`의 `footer`는 선택 prop이라 빼면 하단 영역이 그려지지 않는다.
- 처리 메모:
  - 2026-11-08 완료 (1da9e29): 설정 창 하단 완료 버튼과 쓰지 않는 Button import 제거. 즉시 저장 동작은 그대로.
  - 변경 이력: 처음에는 "창을 닫을 때 한꺼번에 적용"으로 등록했으나, 즉시 저장은 유지하고 완료 버튼만 없애기로 바꿈 (2026-11-08).

### I-002 · 자동 시작 시 완료 팝업을 5초 보여주고 닫힌 뒤 다음 세션 시작
- 종류: 개선
- 우선순위: 보통
- 상태: 완료
- 등록일: 2026-11-08
- 화면/기능: 설정의 "휴식 자동 시작", "집중 자동 시작" / 세션 완료 팝업(`CompletionDialog`)
- 내용: 지금은 자동 시작이 켜져 있으면 세션이 끝나는 순간 다음 세션이 바로 시작되고, 완료 팝업은 "확인"을 누를 때까지 떠 있다. 팝업이 열려 있는 동안 이미 다음 세션 시간이 흐르고, 팝업을 직접 닫아야 한다.
- 기대 동작 (자동 시작이 켜져 있을 때):
  1. 세션이 끝나면 완료 팝업이 자동으로 뜬다.
  2. 팝업에 남은 시간을 보여준다. 예: "5초 후 휴식 시작", "5초 후 집중 시작" (1초마다 줄어듦)
  3. 5초가 지나면 팝업이 저절로 닫히고, **그때부터** 다음 세션이 시작된다. 팝업이 떠 있는 5초 동안 다음 세션 시간은 흐르지 않는다.
  4. 카운트다운 중 팝업에 버튼 두 개를 둔다.
     - **지금 시작**: 기다리지 않고 바로 다음 세션을 시작하고 팝업을 닫는다.
     - **취소**: 이번에는 자동 시작하지 않는다. 팝업을 닫고 다음 세션은 시작 전 상태로 둔다. (자동 시작 설정 자체는 그대로 켜져 있음)
  5. 자동 시작이 꺼져 있을 때의 팝업("나중에", "OO 시작 →")은 지금과 같다.
- 관련 코드:
  - `src/features/timer/timer.ts`: `shouldAutoStart()`와 세션 완료 처리 부분. 지금은 자동 시작이면 다음 세션의 끝나는 시각을 이전 세션이 끝난 시각(`endedAt`) 기준으로 잡아 바로 running 상태로 만든다. 5초 대기 상태(예: `status: "starting"` 또는 `startsAt`)를 추가하거나, 시작 시각을 `endedAt + 5초`로 미루는 방식이 필요하다.
  - `src/features/timer/components/CompletionDialog.tsx`: `nextIsRunning`일 때 "확인" 버튼과 "OO이 자동으로 시작됐어요." 안내를 보여주는 부분을 카운트다운으로 바꾼다.
  - 같은 파일의 `useDelayedOpen`: 집중 완료 시 축하 효과 때문에 팝업이 1초 늦게 열린다(움직임 줄이기 설정이면 바로).
  - `src/features/timer/timer.test.ts`, `store.test.ts`: 자동 시작 관련 테스트 수정 필요.
- 개발 시 확인할 점:
  - **5초 기준 시각:** `setTimeout`이 아니라 시각 기준(예: `endedAt + 대기 시간`)으로 계산해야 한다. 탭이 백그라운드에 있으면 타이머 호출이 늦어지고, 자리를 비운 사이 끝난 경우의 기존 규칙(다음 세션까지 이미 끝났으면 시작 전 상태로 둠)과도 맞아야 한다.
  - **축하 지연 1초:** 팝업이 1초 늦게 열리므로, 5초를 팝업이 열린 시점부터 셀지(사용자가 5초를 온전히 봄) 세션이 끝난 시점부터 셀지 정해야 한다. 제안: 팝업이 열린 시점부터.
  - **취소 이후 상태:** 취소하면 다음 세션은 처음부터 시작 전(대기) 상태여야 한다. 대기 중 흘러간 시간이 빠지면 안 된다.
  - **X·Esc·바깥 클릭으로 닫을 때:** "취소"와 같게 처리하는 것이 자연스럽다. (실수로 닫아도 시간이 몰래 흐르지 않도록)
  - **팝업 안의 다른 기능:** 집중 완료 팝업에는 할 일 완료 체크(`TaskDoneCheck`)가 있어 5초 안에 체크하지 못할 수 있다. 사용자는 "취소"로 멈출 수 있다. 사이클 완료 시의 "수료증 만들기"는 I-004에서 자동 시작 자체를 하지 않기로 해서 카운트다운과 겹치지 않는다.
  - 알림음·브라우저 알림은 지금처럼 세션이 끝날 때 울리고, 다음 세션이 시작될 때 따로 울리지 않는 것으로 가정.
- 처리 메모:
  - 2026-11-08 완료 (f075222)
  - 타이머에 "자동 시작 대기"(`autoStart`) 상태 추가. 세션이 끝나면 다음 세션은 시작 전 상태로 기다리고 시간은 흐르지 않음.
  - 5초는 완료 팝업이 실제로 보인 순간부터 셈 (축하 1초 뒤, 설정·수료증 창이 닫혀 있고, 탭을 보고 있을 때). 시작 시각은 "보인 시각 + 5초" 기준이라 화면 갱신이 늦어도 정확함.
  - 다른 탭에 있거나 자리를 비우면 돌아올 때까지 기다림 (사용자 결정). 카운트다운 중에 자리를 비워 다음 세션 시간까지 지났으면 시작 전 상태로 둠.
  - "취소", X, Esc, 바깥 클릭 = 이번 자동 시작만 취소 (설정은 그대로). "지금 시작" = 바로 시작.
  - 팝업을 아직 못 본 대기는 저장하지 않음 → 그 상태로 새로고침하면 시작 전 상태로 돌아감 (멈춰 있지 않게).
  - 할 일 완료 체크는 한 번 누르면 되어 5초 안에 충분하다고 보고 카운트다운을 멈추지 않음. 수료증은 I-004로 카운트다운 대상에서 빠짐.
  - 2026-11-08: 카운트다운 중 "지금 시작", "취소" 버튼 넣기로 확정.

### I-003 · 설정 창이 열려 있으면 다른 팝업보다 위에 보이게
- 종류: 개선
- 우선순위: 보통
- 상태: 완료
- 등록일: 2026-11-08
- 화면/기능: 설정 창, 세션 완료 팝업(`CompletionDialog`)
- 내용: 설정 창을 보고 있는 중에 세션이 끝나면, 완료 팝업이 설정 창 위에 덮여 뜬다. 설정 창이 항상 다른 팝업보다 위에 있었으면 한다.
- 원인:
  - 모든 팝업이 브라우저 기본 `<dialog>`의 `showModal()`을 쓴다(`src/components/ui/Dialog/Dialog.tsx`). 이렇게 연 팝업은 브라우저의 top layer에 올라가고, **나중에 연 팝업이 무조건 위에** 그려진다. CSS `z-index`로는 순서를 바꿀 수 없다.
  - 반대로 다른 팝업이 떠 있을 때 설정 창을 여는 경우는 없다. 팝업 뒤 화면은 클릭이 막혀 있고, 단축키(S)도 팝업이 열려 있으면 동작하지 않는다(`src/features/shortcuts/shortcuts.ts`의 `dialogOpen`). 그래서 실제로 겹치는 경우는 "설정 창이 열린 뒤 다른 팝업이 새로 뜨는 경우"뿐이다.
- 기대 동작 (제안):
  1. 설정 창이 열려 있는 동안 세션이 끝나면, 완료 팝업은 바로 띄우지 않고 기다린다.
  2. 설정 창을 닫으면 그때 완료 팝업이 뜬다.
  3. 알림음·브라우저 알림은 지금처럼 세션이 끝나는 순간 울린다 (끝난 걸 알 수 있게).
  4. 설정 창 안에서 여는 확인 창(데이터 초기화의 `ConfirmDialog`)은 설정 창 위에 뜨는 지금 동작을 유지한다.
- 관련 코드:
  - `src/features/settings/components/SettingsButton.tsx`: 설정 창 열림 상태(`open`)가 이 컴포넌트 안에만 있다. 완료 팝업이 알 수 있게 공유 상태(스토어 등)로 빼야 한다.
  - `src/features/timer/components/CompletionDialog.tsx`: `open={completed !== null && shown}` 조건에 "설정 창이 닫혀 있을 때"를 추가한다.
- 개발 시 확인할 점:
  - **I-002와 함께 처리:** 자동 시작 카운트다운(5초)은 완료 팝업이 실제로 보인 순간부터 세야 한다. 설정 창이 열려 있는 동안에는 다음 세션이 시작되지 않고 기다려야 한다.
  - 같은 원리로, 앞으로 새로 생기는 자동 팝업도 설정 창이 열려 있으면 기다리게 하는 공통 규칙으로 두면 좋다.
- 처리 메모:
  - 2026-11-08 완료 (f075222, I-002와 함께)
  - 공통 규칙 `useHoldAutoPopups()`(src/lib/popupHold.ts): 사용자가 직접 연 창(설정, 수료증)이 떠 있는 동안 저절로 뜨는 팝업(완료 팝업)을 기다리게 함. 창을 닫으면 그때 뜸.
  - 한 번 뜬 완료 팝업은 그 안에서 연 수료증 창 때문에 닫히지 않음.
  - 알림음·브라우저 알림은 지금처럼 세션이 끝나는 순간 울림.

### I-004 · 사이클을 마치면(수료증 시점) 자동 시작하지 않고 멈춤
- 종류: 개선
- 우선순위: 보통
- 상태: 완료
- 등록일: 2026-11-08
- 화면/기능: 설정의 "휴식 자동 시작", "집중 자동 시작" / 사이클 완료 팝업("한 사이클 완료!")
- 내용: 자동 시작을 켜두면 사이클의 마지막 집중이 끝나도 긴 휴식이 저절로 이어진다. 수료증이 생기는 사이클 완료 시점에는 자동 시작 설정과 상관없이 멈췄으면 한다.
- 기대 동작:
  1. 집중을 `긴 휴식 주기`만큼 마쳐 사이클이 완료되면, "휴식 자동 시작"이 켜져 있어도 긴 휴식을 자동으로 시작하지 않는다.
  2. 이때 뜨는 "한 사이클 완료!" 팝업은 자동 시작이 꺼져 있을 때와 같다: "수료증 만들기", "나중에", "긴 휴식 시작 →". 카운트다운(I-002)은 나오지 않는다.
  3. 사용자가 "긴 휴식 시작 →"을 눌러 긴 휴식을 시작하면, 그 뒤로는 다시 자동 시작 설정대로 동작한다. (긴 휴식이 끝나면 "집중 자동 시작"이 켜져 있을 때 다음 집중을 자동으로 시작)
  4. 사이클 중간의 짧은 휴식, 집중은 지금처럼 자동 시작 설정을 따른다.
- 관련 코드:
  - `src/features/timer/timer.ts`의 `sync()`: 집중이 끝날 때 `completedInCycle >= settings.longBreakInterval`이면 `completed.cycleCompleted = true`를 붙인다. 바로 아래 `shouldAutoStart(next.mode, settings)` 분기에서, 사이클이 완료된 경우는 자동 시작하지 않도록 조건을 추가하면 된다.
  - `src/features/timer/components/CompletionDialog.tsx`: 다음 세션이 시작 전 상태가 되므로 지금의 "나중에 / 긴 휴식 시작 →" 버튼이 그대로 나온다. 별도 수정은 거의 필요 없다.
  - `src/features/timer/timer.test.ts`: "자동 시작이 켜져 있어도 사이클 완료 후에는 idle" 테스트 추가.
- 개발 시 확인할 점:
  - **자리를 비운 경우:** 자리를 비운 사이 사이클이 완료돼도 긴 휴식은 시작 전 상태로 둔다. (위 조건을 `sync()`에 넣으면 함께 해결됨)
  - **I-002와 함께 처리:** 사이클 완료 시에는 5초 카운트다운 대상에서 빠진다.
- 처리 메모:
  - 2026-11-08 완료 (13d20ec): `sync()`에서 사이클 완료 시 자동 시작하지 않음. 긴 휴식을 직접 시작하면 그 뒤로는 다시 자동 시작을 따름.

### I-005 · 헤더의 타이머·캘린더 메뉴에 아이콘 사용 (휴대폰은 아이콘만)
- 종류: 개선
- 우선순위: 낮음
- 상태: 완료
- 등록일: 2026-11-08
- 화면/기능: 헤더의 페이지 이동 메뉴 (타이머 / 캘린더)
- 내용: 지금은 "타이머", "캘린더" 글자 탭이다. 아이콘을 넣어 헤더를 정돈하고, 좁은 화면에서 공간을 아끼고 싶다.
- 기대 동작:
  1. **넓은 화면** (`sm` 480px 이상): 아이콘 + 글자를 함께 보여준다. 예: [시계 아이콘] 타이머 · [달력 아이콘] 캘린더
  2. **휴대폰** (480px 미만): 아이콘만 보여준다.
  3. 지금 있는 페이지가 한눈에 보여야 한다. 지금의 "진하게 + 아래 강조색 줄"을 유지하거나, 아이콘만 있을 때 알아보기 쉬운 방식(배경 강조 등)으로 바꾼다.
  4. 아이콘만 보일 때도 마우스를 올리면 이름(툴팁)이 뜨고, 화면 읽기 프로그램에는 "타이머", "캘린더"로 읽힌다.
- 관련 코드:
  - `src/components/layout/AppNav.tsx`: `PAGES` 배열에 아이콘을 추가하고 링크 안에 아이콘 + 글자를 그린다.
  - `src/components/layout/AppNav.module.scss`: 480px 미만에서 글자를 숨긴다. 이때 `display: none`이 아니라 `mixins.visually-hidden`(`src/styles/_mixins.scss`)으로 숨겨야 화면 읽기 프로그램이 이름을 읽는다. 기준점은 `src/styles/_breakpoints.scss`의 `bp.down(sm)` / `bp.up(sm)`.
  - `src/components/icons/icons.tsx`: 타이머(시계 또는 스톱워치), 캘린더 아이콘이 없어서 새로 추가해야 한다. 기존 아이콘(`SettingsIcon` 등)과 선 두께·크기를 맞춘다.
- 개발 시 확인할 점:
  - 메뉴는 버튼이 아니라 링크(`Link`)다. `IconButton`을 그대로 쓰지 말고 링크와 `aria-current="page"`를 유지한다. 툴팁은 설정 버튼과 같은 방식으로 맞춘다.
  - 아이콘만 있을 때 누르는 영역이 너무 작지 않게, 다른 아이콘 버튼과 같은 크기(`--control-sm` 이상)로 맞춘다.
  - 새 아이콘을 추가하면 디자인 시스템 문서(`docs/06-design-system.md`)에도 적는다.
- 처리 메모:
  - 2026-11-08 완료 (ec3c1da): 시안 두 개(밑줄 / 둥근 배경) 중 **둥근 배경**으로 결정. 지금 페이지는 둥근 흰 배경 + 강조색 아이콘·글자.
  - 아이콘 `TimerIcon`(스톱워치), `CalendarIcon` 추가. 480px 미만은 아이콘만, 이름은 `visually-hidden`으로 남기고 `title`로 툴팁. 누르는 영역 32px.
  - 메뉴가 아이콘만 보이면서 자리가 생겨, 360px 미만에서 숨기던 🌙 테마 버튼을 다시 보이게 함 (320px까지 확인).

### I-006 · 집중 소리 선택 창 UI 정리 (소리별 아이콘 추가)
- 종류: 개선
- 우선순위: 보통
- 상태: 완료
- 등록일: 2026-11-08
- 화면/기능: 헤더의 헤드폰 버튼 → 집중 소리 고르기 창 (`FocusSoundPanel`)
- 내용: 지금은 소리 칸이 이름 + 짧은 설명 글자로만 되어 있어 밋밋하고 한눈에 구분이 안 된다. 아이콘을 넣고 전체적으로 깔끔하게 다듬고 싶다.
- 지금 구성: 제목 "집중 소리" + 안내 문구 → "끄기"(한 줄) → "노이즈" 3개, "자연의 소리" 5개(2칸 격자, 이름 + 설명) → 소리 크기 슬라이더
- 기대 동작 (방향 제안):
  1. **소리마다 아이콘:** 칸마다 아이콘을 넣어 글자를 읽지 않고도 구분되게 한다.
     - 끄기: 소리 끔(스피커에 사선)
     - 백색소음 / 핑크 노이즈 / 브라운 노이즈: 파형 아이콘. 촘촘함·높이를 다르게 해 세 가지를 구분 (예: 촘촘한 파형 → 완만한 파형 → 낮고 굵은 파형)
     - 빗소리: 비구름 / 창가 빗소리: 창문과 빗방울 / 모닥불: 불꽃 / 숲속: 나무 / 파도: 물결
  2. **칸 모양:** 아이콘을 위(또는 왼쪽)에 크게, 그 아래 이름. 설명은 작고 흐리게 두거나, 칸이 복잡해 보이면 마우스를 올렸을 때만 보여준다.
  3. **고른 소리 표시:** 지금의 강조색 테두리·배경에 더해 아이콘도 강조색으로 바꾼다. 집중 중이라 실제로 재생 중이면 작은 재생 표시(움직이는 막대 등)를 붙인다. 움직임 줄이기 설정이면 움직이지 않는다.
  4. **소리 크기:** 슬라이더 양쪽에 작은 소리·큰 소리 스피커 아이콘을 둔다. "끄기"일 때는 지금처럼 비활성.
  5. **머리 부분:** 제목 옆에 헤드폰 아이콘. 안내 문구는 한 줄로 짧게 다듬는다.
  6. 전체적으로 칸 사이 간격·여백을 정리하고, 그룹 제목("노이즈", "자연의 소리")과 칸이 한 덩어리로 보이게 한다.
- 관련 코드:
  - `src/features/focus-sound/components/FocusSoundPanel.tsx`, `FocusSoundPanel.module.scss`: 창 내용과 칸(`SoundOption`) 모양.
  - `src/features/focus-sound/sounds.ts`: `FOCUS_SOUNDS`에 소리별 아이콘(또는 아이콘 이름)을 추가하면 칸에서 꺼내 쓰기 쉽다.
  - `src/components/icons/icons.tsx`: 필요한 아이콘을 새로 추가한다 (지금은 `HeadphonesIcon`만 관련 있음). 기존 아이콘과 선 두께·크기를 맞춘다.
  - `src/features/focus-sound/components/FocusSoundButton.module.scss`: 창 너비 `min(320px, …)`. 아이콘을 넣어 칸이 커지면 너비나 격자 칸 수(지금 2칸)를 다시 정한다.
- 개발 시 확인할 점:
  - 칸 전체가 라디오 버튼인 지금 구조(키보드·화면 읽기 프로그램 지원)는 유지한다. 아이콘은 장식이므로 `aria-hidden`.
  - 휴대폰 너비(360px 근처)에서도 칸 이름이 잘리지 않는지 확인한다.
  - 밝은/어두운 테마 모두에서 아이콘 대비를 확인한다.
  - 새 아이콘은 `docs/06-design-system.md`에도 적는다.
- 처리 메모:
  - 디자인 세부(아이콘 위치, 설명 표시 여부)는 확정 전. 시안을 먼저 보고 정할 수 있음.
  - 2026-11-08 완료 (0d5c358): 시안 두 개(아이콘 왼쪽 + 설명 / 아이콘 위 세 칸) 중 **아이콘 위, 세 칸**으로 결정. 설명은 칸에서 숨기고 마우스를 올리면 툴팁, 화면 낭독기는 이름과 설명을 함께 읽음 ("끄기" 줄만 설명 표시).
  - 아이콘 11개 추가: 끄기·작은 소리·큰 소리 스피커, 노이즈 3종 파형, 비구름, 창문, 불꽃, 나무, 물결. 소리 목록(`FOCUS_SOUNDS`)에 `icon`.
  - 고른 소리는 강조색 테두리·아이콘, 집중 중이면 오른쪽 위에 오르내리는 막대 3개(움직임 줄이기면 멈춤, 화면 낭독기는 "재생 중"). 소리 크기 막대 양쪽에 스피커 아이콘(`Slider`의 `startIcon`, `endIcon`). 제목 옆 헤드폰.
  - 창 너비 320 → 340px. 아주 좁은 화면(360px 미만)에서 "브라운 노이즈"는 띄어쓰기에서 줄바꿈. 아이폰 13 높이에서 한 화면에 다 보임.

### I-007 · (나중에) 집중 소리에 따라 배경 바꾸기
- 종류: 개선
- 우선순위: 낮음 (당장 하지 않음. 나중에 넣고 싶은 아이디어)
- 상태: 열림
- 등록일: 2026-11-08
- 화면/기능: 타이머 화면 배경 / 집중 소리
- 내용: 고른 집중 소리에 맞춰 화면 배경이 바뀌었으면 한다. 예: 빗소리 → 비 오는 창가 분위기, 모닥불 → 따뜻한 불빛, 숲속 → 초록 숲, 파도 → 바다.
- 정하지 않은 것 (작업 전에 정해야 함):
  - **언제 바뀌나:** 소리를 고르기만 해도 바뀌는지, 집중 중이라 실제로 소리가 나올 때만 바뀌는지. (소리는 집중 중에만 재생되고 휴식 때는 꺼짐)
  - **어떤 배경:** 색·그라데이션만 바꾸는지, 일러스트·사진인지, 빗방울·불꽃 같은 움직이는 효과까지 넣는지.
  - **노이즈 3종(백색·핑크·브라운):** 배경을 바꿀지, 기본 배경을 쓸지.
  - **까미(마스코트)와 어울림:** 소리별 배경에 까미를 함께 넣을지.
- 관련 코드:
  - `src/app/_components/AppShell.tsx`: 화면 전체에 `data-mode={mode}`(집중/휴식)가 붙어 있다. 같은 방식으로 `data-sound` 같은 값을 붙이면 CSS로 배경을 바꿀 수 있다.
  - `src/styles/globals.scss`, `src/styles/tokens/_color.scss`: 기본 배경 `--color-bg` (밝은 테마 cream, 어두운 테마 night).
  - `src/features/focus-sound/sounds.ts`: 소리 목록 `FOCUS_SOUNDS`. 소리별 배경 정보를 여기에 붙일 수 있다.
- 개발 시 확인할 점:
  - 배경이 바뀌어도 타이머 숫자·버튼 글자가 잘 읽히는지 (밝은/어두운 테마 모두).
  - 움직이는 배경은 "움직임 줄이기" 설정이면 멈춘다.
  - 이미지·영상 배경은 용량이 커서 처음 고를 때만 받도록 (녹음 소리 파일처럼).
