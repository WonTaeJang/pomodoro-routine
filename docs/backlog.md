## 처리 규칙

- 독립적으로 추적할 기능·버그를 등록합니다. 같은 작업의 문구·포맷·문서 보완은 별도 항목으로 쪼개지 않습니다.
- 번호는 완료 목록까지 포함해 이어서 매기며 재사용하지 않습니다. 현재 마지막 번호는 `I-073`, `B-013`입니다.
- `열림` → `진행 중` → 구현·필요한 검증 후 `완료`. 미루기로 한 작업은 `보류`와 이유를 남깁니다.
- 목적·완료 조건·상태·우선순위를 기본으로 쓰고, 버그 재현 방법과 의존성·미정 사항은 필요한 만큼만 덧붙입니다. 우선순위는 높음(사용 지장)·보통·낮음입니다.
- 완료 항목은 이 파일에서 빼고 완료 목록에 결과 한 줄을 남깁니다. 커밋·버전은 이미 알 때만 적으며, 해시를 채우기 위한 후속 커밋은 만들지 않습니다.
- 관련 테스트·문서·백로그 상태는 구현과 같은 커밋에 포함합니다. 커밋 보류 요청이 있으면 검증 여부와 미커밋 상태를 구분해 적습니다.
- 확정 설계는 결정 문서, 구현 방법은 해당 구현 문서에 둡니다. 백로그에는 링크와 남은 일만 남기며 버전 규칙은 여기서 중복 정의하지 않습니다.

### I-072 · 까미 미니게임: 합치기 게임 (수박 게임 방식)

- 상태: 열림
- 우선순위: 보통
- 목적: 다마고치(까미 돌봄)에 이어 두 번째 놀이로, 같은 것 둘이 부딪히면 한 단계 큰 것으로 합쳐지는 "수박 게임" 방식의 미니게임을 까미 테마로 넣는다.
- 완료 조건 (제안, 사용자 확인 전):
  - **규칙:** 위에서 좌우로 움직여 떨어뜨리고, 같은 단계끼리 닿으면 합쳐져 다음 단계가 되며 점수. 통 위 선을 넘겨 쌓이면 게임 끝. 다음에 떨어질 것 미리 보기.
  - **까미 테마 단계 (예시, 작은 것 → 큰 것):** 발바닥 도장 → 나뭇잎 → 꽃 → 솔방울 → 돌멩이 → 공 → 뼈다귀 → 간식 그릇 → 방석 → 까미 얼굴 → 행복한 까미(최종). 다마고치의 도트 그림체와 맞춤.
  - **조작:** 마우스 이동·클릭, 휴대폰 터치로 끌다 놓기, 키보드(← → 이동, Space 떨어뜨리기). 휴대폰 세로 화면에 맞는 통 크기.
  - **점수:** 이번 점수와 최고 점수. 최고 점수는 브라우저에 저장, 로그인하면 계정에도(I-064 까미 기록과 함께).
  - **들어가는 곳:** 다마고치 화면에서 "놀이" 버튼 또는 메뉴. 페이지 주소 예: `/pet/merge`.
  - "움직임 줄이기"면 합쳐질 때 튀는 효과를 줄임. 탭을 벗어나면 일시정지. 효과음은 알림음 설정과 따로 끄고 켤 수 있게.
  - 문구 ko/en.
- 참고:
  - **이름·그림:** "수박 게임"은 다른 회사의 게임 이름이고 그림도 그쪽 것이므로 그대로 쓰지 않는다. 규칙(합치기)만 빌리고 이름·그림은 까미 것으로 새로 만든다. 이름 예: "까미 합치기", "발바닥 쌓기".
  - **뽀모도로와의 관계:** 집중 중에 게임을 하면 앱의 목적과 어긋남. 제안: 휴식 중이거나 타이머가 쉬고 있을 때만 시작 가능, 집중 중에는 "휴식 때 놀아요" 안내. 휴식이 끝나면 게임을 일시정지하고 집중으로 돌아가자고 알림(I-065의 휴식 데려가기와 연결).
  - **물리 엔진:** 원이 서로 밀고 굴러야 해서 2D 물리 계산이 필요. 라이브러리(Matter.js 등, 용량 확인) 또는 원 충돌만 직접 구현. I-068(Rive 빼고 캔버스로 까미 그리기)처럼 캔버스로 그리면 다마고치와 같은 방식.
  - **보상 연결(선택):** 일정 점수마다 산책 아이템이나 발바닥 도장. 하루 한도를 둬야 게임만 해서 아이템을 모으는 일이 없음.
  - 미정: 게임 이름, 단계 구성과 그림, 집중 중 제한 여부, 보상 연결 여부, 점수 순위(로그인 사용자끼리) 여부.

### I-073 · 계절 재료와 계절 가구 세트

- 상태: 열림
- 우선순위: 보통
- 목적: 계절마다 산책에서만 주울 수 있는 재료를 추가하고, 그 재료를 가지고 있을 때만 만들기·세트 목록에 나타나는 계절 가구 세트를 만든다. 계절이 바뀔 때마다 새로 모으는 재미.
- 완료 조건 (제안, 사용자 확인 전):
  - **계절 재료 (예시):** 봄 벚꽃잎, 여름 조개껍데기, 가을 단풍잎, 겨울 눈송이. 그 계절에만 산책 줍기 후보에 들어간다(기존 6종과 함께 확률로).
  - **계절 세트 (예시, 벽·바닥 / 창문 / 화분 / 카펫 한 벌):** 봄 벚꽃 정원, 여름 바닷가, 가을 단풍 산장, 겨울 눈 오두막(크리스마스 장식). 재료는 계절 재료 + 기존 아이템(궁전 세트처럼 "특별 재료 1 + 같은 아이템 2" 방식).
  - **보이는 조건:** 그 계절 재료를 하나라도 가진 적이 있으면(주운 적이 있으면) 아이템 상자 만들기 탭·세트 탭에 해당 계절 세트가 나타난다. 한 번도 줍지 않았으면 목록에 없다.
  - **계절이 끝난 뒤:** 이미 주운 재료와 만든 가구는 그대로 남고 계속 쓸 수 있다. 줍기 후보에서만 빠진다.
  - 아이템 상자 "얻는 방법"(?)에 "봄(3~5월) 산책에서" 같은 안내. 그 계절이 아니면 "다음 봄에 다시 나와요".
  - 이름 ko/en, 저장 형식 버전 올리기, 계정 저장(I-064)에도 반영.
- 참고:
  - 지금 구조: 산책 아이템 6종·확률([결정 문서 · 산책](./03-decisions.md)), 만들기·세트(`src/features/pet/furniture.ts`의 `SETS`, 그림 `roomArt.ts`), 세트 탭(I-069), 궁전 세트(I-067)·아이돌 무대(I-071)가 "조건이 맞을 때만 보이는 세트"의 앞선 예(아이돌 무대는 VIP만).
  - **계절 기준:** 기기 로컬 날짜의 월로 판단(산책 하루 한도와 같은 기준). 제안: 봄 3~5월, 여름 6~8월, 가을 9~11월, 겨울 12~2월. 남반구는 고려하지 않음.
  - **보이는 조건 판단:** "지금 가진 개수"가 아니라 "주운 적이 있는지"로 해야, 재료를 다 써서 0개가 됐을 때 만든 세트가 목록에서 사라지는 일이 없음. 받은 수·쓴 수를 나누는 지금 저장 방식으로 판단 가능.
  - 겨울 세트의 창밖은 눈 내리는 풍경, 낮·밤 시간대 전환(I-054)과 함께.
  - 미정: 계절 재료 종류, 계절 세트 디자인, 계절 재료의 줍기 확률, 계절 기준(월 단위/특정 기간 이벤트), 지금 계절(가을)부터 시작할지.
