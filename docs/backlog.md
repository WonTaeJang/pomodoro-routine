## 처리 규칙

- 독립적으로 추적할 기능·버그를 등록합니다. 같은 작업의 문구·포맷·문서 보완은 별도 항목으로 쪼개지 않습니다.
- 번호는 완료 목록까지 포함해 이어서 매기며 재사용하지 않습니다. 현재 마지막 번호는 `I-071`, `B-013`입니다.
- `열림` → `진행 중` → 구현·필요한 검증 후 `완료`. 미루기로 한 작업은 `보류`와 이유를 남깁니다.
- 목적·완료 조건·상태·우선순위를 기본으로 쓰고, 버그 재현 방법과 의존성·미정 사항은 필요한 만큼만 덧붙입니다. 우선순위는 높음(사용 지장)·보통·낮음입니다.
- 완료 항목은 이 파일에서 빼고 완료 목록에 결과 한 줄을 남깁니다. 커밋·버전은 이미 알 때만 적으며, 해시를 채우기 위한 후속 커밋은 만들지 않습니다.
- 관련 테스트·문서·백로그 상태는 구현과 같은 커밋에 포함합니다. 커밋 보류 요청이 있으면 검증 여부와 미커밋 상태를 구분해 적습니다.
- 확정 설계는 결정 문서, 구현 방법은 해당 구현 문서에 둡니다. 백로그에는 링크와 남은 일만 남기며 버전 규칙은 여기서 중복 정의하지 않습니다.

  - 이름·설명 ko/en.

### I-070 · VIP 매일 선물 상자 (다마고치)

- 상태: 열림
- 우선순위: 보통
- 목적: VIP 계정이 다마고치(까미 돌봄) 화면에서 하루 한 번 선물 상자를 열어 아이템을 받는다.
- 기존 결정과 달라지는 점: 지금 VIP는 "프로필 배지만, 기능 차이 없음(유료 아님)"으로 정해져 있다([결정 문서 · 관리자 페이지와 VIP](./03-decisions.md), I-015). 이 항목부터 **VIP에게 기능 혜택이 생긴다.** 결정 문서를 함께 고친다. 유료가 아니라 운영자가 켜 주는 혜택이라는 점은 그대로.
- 완료 조건 (제안, 사용자 확인 전):
  - **보이는 사람:** VIP로 켜진 로그인 계정. 다마고치 방(또는 아이템 상자 옆)에 선물 상자 아이콘, 오늘 아직 안 열었으면 빨간 점.
  - **하루 한 번:** 열면 상자가 흔들리다 열리는 짧은 연출 → 받은 아이템 카드 → 아이템 상자에 들어감, 기록창에 한 줄. 연 뒤에는 "내일 다시 열 수 있어요"(다음 열 수 있는 시각 표시).
  - **내용물 (예시):** 산책 아이템 6종 중 무작위 2~3개, 가끔 발바닥 도장 1개. 하트는 친밀도 보상이라 넣지 않는 쪽 제안.
  - **중복 방지는 서버에서:** 받은 기록을 계정에 저장하고 Supabase 함수가 "오늘 이미 받았는지"를 확인한 뒤 내용물을 정해 돌려준다. 브라우저 저장만 쓰면 기기 여러 대·저장 지우기로 여러 번 받을 수 있음. 탭 여러 개에서 동시에 눌러도 한 번만.
  - **날짜 기준:** 하루가 바뀌는 시각을 정한다(제안: 한국 시간 자정, 또는 기기 로컬 자정 — 산책 하루 5번은 기기 로컬 날짜를 쓰고 있음).
  - VIP가 꺼지면 상자가 사라짐. 이름·설명 ko/en. "움직임 줄이기"면 흔들림 없이 바로 열림.
- 참고:
  - VIP 확인: `vip_users` 표(본인 행만 읽기), `src/features/admin/useAccountFlags.ts`, `supabase/admin.sql`. 권한·지급은 화면이 아니라 서버 함수에서 확인(`security definer` + VIP 확인).
  - 아이템 반영: 까미 기록 계정 저장(I-064, `supabase/pet-game.sql`의 돌봄 기록)에 "선물 상자로 받은 아이템"으로 쌓으면 다른 기기에도 들어감. 받은 수·쓴 수를 나누는 지금 저장 방식(방 꾸미기·발바닥 도장)과 맞춤.
  - 아이템 상자 "얻는 방법" 팝업(?)에 "VIP 선물 상자" 추가.
  - 미정: 내용물과 개수·확률, 날짜 기준, VIP가 아닌 사람에게 잠긴 상자를 보여 줄지(제안: 보여 주지 않음), 연속으로 열면 더 좋은 선물을 줄지.
